Plynulé přechody stavů: Vlastnost transition

Zajistí, aby se barva, poloha nebo stín neměnily skokově, ale animovaly se v čase.

4 parametry vlastnosti transition 
/* Zkratka: [vlastnost] [doba] [časování] [zpoždění] */
transition: background-color 0.3s ease 0.1s;

/* Animace více vlastností oddělených čárkou: */
transition: transform 0.25s ease, opacity 0.3s linear;
  • transition-property: Která vlastnost se animuje (např. transform, opacity).
  • transition-duration: Doba trvání v sekundách či milisekundách (např. 0.3s, 200ms).
  • transition-timing-function: Průběh rychlosti (ease, linear, ease-in-out).
  • transition-delay: Zpoždění před startem přechodu.
Častá chyba: transition: all;

Zápis transition: all 0.3s; nutí prohlížeč hlídat a přepočítávat každou změnu ve stylopisu.

Správná praxe: Vždy explicitně jmenujte vlastnosti, které chcete animovat (např. transition: transform 0.2s, box-shadow 0.2s;). Šetříte procesor i baterii mobilu.

2D Transformace: Posun, Zvětšení, Rotace a Zkosení

Měňte geometrii prvků bez toho, aby to ovlivnilo polohu sousedních boxů v toku stránky.

Čtyři základní funkce transform 
/* 1. Posun o X a Y: */
transform: translate(20px, -10px);

/* 2. Zvětšení / zmenšení měřítka: */
transform: scale(1.15); /* +15 % */

/* 3. Rotace ve stupních (deg): */
transform: rotate(45deg);

/* 4. Zkosení: */
transform: skewX(-15deg);
Skládání a kotevní bod

Kombinace více transformací

Transformace lze libovolně řetězit za sebe:

.card:hover {
  transform: translateY(-6px) scale(1.03) rotate(-1deg);
}

Vlastnost transform-origin: center; určuje střed otáčení a zvětšování (výchozí střed lze změnit např. na top left).

3D transformace v CSS: Perspektiva a otočné karty

Vytvořte iluzi trojrozměrné hloubky a prostorového otáčení objektů přímo na monitoru.

Vlastnost perspective na rodiči

Bez perspektivy vypadá 3D rotace jen jako plošné splácnutí. Vlastnost perspective: 800px; definuje vzdálenost oka pozorovatele od obrazovky: 

.scene {
  perspective: 1000px; /* 3D hloubka */
}
.box-3d {
  transform: rotateY(45deg) rotateX(15deg);
  transform-style: preserve-3d;
}

Plnohodnotné animace: Časová osa @keyframes

Zatímco transition umí pouze přechod z bodu A do bodu B, @keyframes nabízí neomezenou časovou osu.

Definice klíčových snímků

Animaci pojmenujeme a určíme její průběh od 0 % do 100 %:

@keyframes pulseGlow {
  0% {
    transform: scale(1);
    box-shadow: 0 0 0 0 rgba(139, 92, 246, 0.6);
  }
  70% {
    transform: scale(1.08);
    box-shadow: 0 0 0 14px rgba(139, 92, 246, 0);
  }
  100% {
    transform: scale(1);
  }
}
Jak animaci spustit na prvku?

Přiřadíme název animace a dobu trvání vlastností animation:

.btn-pulse {
  animation: pulseGlow 2s infinite ease-in-out;
}
  • infinite: Animace se opakuje donekonečna.
  • Lze specifikovat i přesný počet opakování (např. 3).

Parametry vlastnosti animation

Podrobná kontrola nad směrem běhu, opakováním a chováním po skončení animace.

Klíčové podvlastnosti
  • animation-iteration-count: Počet opakování (číslo nebo infinite).
  • animation-direction: Směr přehrávání: normal, reverse, alternate (tam a zpět jako kyvadlo!).
  • animation-play-state: Možnost pozastavení animace: running nebo paused (např. na hover!).
Zásadní vlastnost: animation-fill-mode

Co se stane, když neopakovaná animace doběhne do konce?

/* Prvek zůstane ve stavu 100% a nevrátí se na začátek: */
animation-fill-mode: forwards;

Bez forwards prvek po skončení animace okamžitě „blikne“ zpět do svého původního výchozího stavu.

Výkon a plynulost (60/120 FPS): GPU akcelerace

Rozdíl mezi drahým přepočítáváním stránky (Layout/Paint) a bleskovým vykreslováním na grafické kartě (Composite).

Dvě bezpečné vlastnosti pro GPU

Pokud chcete naprosto plynulé animace bez sekání procesoru, animujte výhradně:

1. transform (translate, scale, rotate)
2. opacity (průhlednost)

Tyto vlastnosti běží přímo na grafickém čipu (GPU) ve fázi Composite a nezatěžují hlavní procesorové vlákno.

Černé pole: Co NIKDY neanimovat

Nikdy neanimujte vlastnosti, které vyvolávají Reflow / Layout:

/* ZÁKAZ animování: vyvolává záseky! */
width, height, top, left, margin, padding

Při změně např. top musí prohlížeč přepočítat geometrii celé stránky pro každý jeden snímek (60krát za sekundu). Na mobilu se animace okamžitě začne trhat.

Optimalizace výkonu a vlastnost will-change

Jak předem upozornit prohlížeč na nadcházející animaci a proč to nepřehánět.

Včasná příprava vrstvy

Pokud víte, že prvek bude náročně animován, sdělte to prohlížeči předem: 

.heavy-card {
  will-change: transform, opacity;
}

Prohlížeč pro tento prvek předem vytvoří samostatnou hardwarovou vrstvu v paměti GPU a animace začne okamžitě bez prodlevy.

Varování: Šetřete paměť!

Nikdy nenastavujte will-change na všechny prvky v kódu (* { will-change: all; }).

Každá nová GPU vrstva spotřebovává operační a grafickou paměť. Příliš mnoho vrstev může vést k pádu prohlížeče v mobilním telefonu.

Budoucnost: Scroll-driven animace v čistém CSS

Animace řízené posunem stránky (scrollováním) bez nutnosti instalovat těžké JavaScriptové knihovny.

animation-timeline: scroll()

Časová osa animace není vázána na vteřiny, ale na procento odscrollované stránky: 

/* Ukazatel čtení (Progress bar na horní liště): */
@keyframes growProgressBar {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

.reading-progress-bar {
  animation: growProgressBar linear;
  animation-timeline: scroll();
}
Proč je to revoluční?
  • Běží mimo hlavní vlákno JavaScriptu → ani při rychlém rolování se nezasekne.
  • Už není potřeba instalovat knihovny jako GSAP ScrollTrigger pro základní efekty postupného odkrývání prvků (Reveal on scroll).

Shrnutí tématu a opakovací otázky

Ověřte si své porozumění CSS animacím, časování, 3D prostoru a pravidlům GPU akcelerace.

01. Proč je pro plynulost animace bezpečné animovat transform a opacity, ale ne top nebo width?
Vlastnosti transform a opacity jsou zpracovávány přímo na grafické kartě (GPU) v tzv. Composite fázi. Změna top či width naproti tomu nutí prohlížeč v každém snímku znovu přepočítat geometrii celé stránky (Reflow/Layout), což vyvolává zasekávání na mobilních zařízeních.
02. V čem se liší vlastnost transition od animace definované pomocí @keyframes?
transition vyžaduje změnu stavu (např. :hover) a animuje pouze plynulý přechod mezi výchozím a cílovým stavem (A → B). @keyframes je plnohodnotná animace běžící samostatně s libovolným množstvím mezilehlých kroků na časové ose (0 % až 100 %) a může se opakovat nekonečně.
03. K čemu slouží vlastnost animation-fill-mode: forwards;?
Zajistí, že po doběhnutí animace prvek zůstane ve svém finálním stavu (ve 100% klíčovém snímku). Bez tohoto nastavení by prvek okamžitě po skončení blikl zpět do svého původního nestylovaného stavu před animací.
04. Co způsobuje vlastnost perspective u 3D transformací?
Vytváří iluzi hloubky prostoru (definuje pomyslnou vzdálenost oka pozorovatele od plochy monitoru). Bez perspektivy vypadá 3D rotace pouze jako ploché smrštění nebo deformace, teprve s ní získává objekt realistické zkosení vzdalujících se hran.
