Běžný tok dokumentu (Normal Flow) a position: static

Jak prohlížeč přirozeně řadí prvky a proč na static nefungují souřadnice.

Výchozí chování prohlížeče

  • Výchozí hodnota pro všechno: Každý HTML element má automaticky position: static;, pokud nestanovíte jinak.
  • Pořadí podle DOM stromu: Blokové elementy (div, p, h1) se řadí shora dolů pod sebe. Řádkové (span, a) plynou vedle sebe zleva doprava jako slova ve větě.
  • Rezervované místo: Každý prvek si v toku stránky nárokuje přesný prostor daný svým box modelem.

Častá chyba začátečníků: Souřadnice

Pokud má prvek position: static, prohlížeč zcela ignoruje vlastnosti:

top: 50px;     /* Ignorováno! */
right: 20px;   /* Ignorováno! */
bottom: 0;     /* Ignorováno! */
left: 10px;    /* Ignorováno! */
z-index: 100;  /* Ignorováno! */

Chceme-li prvek někam posunout pomocí souřadnic nebo vrstvit pomocí z-index, musíme změnit typ pozicování na relative, absolute, fixed nebo sticky.

Relativní (relative) vs. Absolutní (absolute) pozicování

Rozdíl mezi posunem vůči původnímu místu a vytržením prvku do nového vztažného rámce.

position: relative

Relativní posun vůči sobě samému

  • Prvek se posune o top, left apod. ze své původní pozice.
  • Místo v toku zůstává rezervované! Ostatní prvky na stránce se neposunou, jako by prvek stále stál na svém místě.
  • Slouží jako kotevní bod pro své absolutně pozicované potomky.
.posunuty-box {
  position: relative;
  top: 20px;
  left: 25px;
}
position: absolute

Vytržení z toku & Hledání kotevního rodiče

  • Prvek je vytržen z toku: Nezanechává za sebou žádné prázdné místo, okolní prvky se semknou.
  • Vůči komu se počítají souřadnice? Vůči nejbližšímu předkovi, který má pozici jinou než static (typicky relative).
  • Nenajde-li žádného takového předka, ukotví se vůči kořenu stránky (oknu prohlížeče).
.rodic { position: relative; }
.odznak-v-rohu {
  position: absolute;
  top: 10px;
  right: 10px;
}

Fixní (fixed) a Lepivé (sticky) pozicování

Vytváření plovoucích prvků, stálých hlaviček a interaktivních postranních panelů.

position: fixed (Přišpendleno k oknu)

  • Prvek je vytržen z toku a ukotven přímo k průzoru prohlížeče (viewportu).
  • Při scrollování stránky zůstává stále na stejném místě na obrazovce.
  • Typické využití: Vždy viditelná horní navigační lišta, tlačítko „Zpět nahoru“ v pravém dolním rohu, lišta pro cookies.
.top-navbar {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  z-index: 1000;
}

position: sticky (Chytré přilepení)

  • Hybrid mezi relative a fixed.
  • Zpočátku se chová jako běžný prvek v toku. Jakmile však uživatel doscrolluje k zadané hranici (např. top: 0), prvek se přilepí k obrazovce.
  • Pozor na rodiče: Lepí se pouze v rámci hranic svého přímého rodiče. Pokud rodič odroluje z obrazovky, odroluje s ním i sticky prvek!
.table-header {
  position: sticky;
  top: 0; /* Povinná souřadnice pro přilepení! */
  background: #1e293b;
}

Třetí rozměr v CSS: z-index a Stacking Context

Jak funguje vrstvení prvků nad sebou a proč samotné zvětšování čísla z-indexu na 999 999 často vůbec nepomáhá.

Teorie & Pravidla

Hierarchie vrstvení a analogie kapitol

Vlastnost z-index určuje pozici prvku na ose Z (kolmo k monitoru). Funguje však pouze na pozicovaných prvcích (ne na static).

Princip kapitol (Krabice v krabici):
Prvky uvnitř kontextu vrstvení soupeří pouze mezi sebou. Rodič s z-index: 1 vytvoří úroveň 1.x. Rodič s z-index: 2 úroveň 2.x.
Potomek A = 1.999999  <  Potomek B = 2.000001

Co zakládá nový Stacking Context?

  • position: relative / absolute s číselným z-index (ne auto)
  • position: fixed nebo sticky
  • opacity < 1 (častá záludnost při animacích!)
  • transform, filter, backdrop-filter jiné než none
  • isolation: isolate (bezpečné uzavření kontextu komponenty)
Živý experiment Rodič B je navrchu (2 > 1)

Proč z-index 999 999 prohrává?

📁 Rodič A (Kontext 1) z-index: 1
📄 Potomek A
z-index: 999 999
Uvězněn v Rodiči A (úroveň 1.x)
📁 Rodič B (Kontext 2) z-index: 2
📄 Potomek B
z-index: 1
Překrývá Potomka A! (úroveň 2.x)

Výchozí stav: Potomek B (oranžový) leží NAD Potomkem A (zeleným), i když má z-index jen 1 oproti 999 999! Rodič B má totiž z-index: 2, který poráží Rodiče A s z-index: 1.

Revoluce jménem Flexbox: Konec trápení s layoutem

Flexible Box Layout – nativní standard pro moderní jednorozměrné rozvržení obsahu.

Proč Flexbox změnil webový vývoj?

V minulosti se weby stavěly pomocí tabulek a později obtékání (float a clearfix). Vycentrovat prvek svisle byla noční můra každého kodéra.

  • Jednorozměrný (1D): Řeší rozvržení buď v řádku, nebo ve sloupci (na rozdíl od 2D Gridu).
  • Přirozená pružnost: Prvky se automaticky roztahují nebo smršťují podle volného místa na displeji.
  • Hračka pro centrování: Vycentrování na střed obou os zabere pouhé 3 řádky kódu!

Koncept: Rodič (Container) a Potomci (Items)

Flexbox dělí pravidla striktně do dvou kategorií:

1. Flex Container (Obal / Rodič):
Aktivuje se pomocí display: flex;. Nastavuje směr toku, zalamování a celkové zarovnání potomků.
2. Flex Items (Položky / Přímé děti):
Všechny přímé elementy uvnitř kontejneru se stanou flexibilními. Určují svou pružnost, schopnost růst, smršťovat se a vlastní individuální zarovnání.

Hlavní osa, příčná osa a zalamování (flex-wrap)

Základní geometrie: pochopení, která osa je hlavní, určuje fungování všech ostatních vlastností.

flex-direction

Směr toku: Která osa je hlavní?

Výchozí směr je row (vodorovný řádek zleva doprava).

flex-direction: row; → Hlavní osa je vodorovná (X), příčná osa svislá (Y).
flex-direction: column; → Prohození os! Hlavní osa je svislá (shora dolů), příčná vodorovná.
row-reverse / column-reverse → Otočí pořadí prvků v opačném směru.
flex-wrap

Zalamování do více řádků

Ve výchozím stavu se Flexbox zuby nehty snaží nacpat všechny prvky do jednoho jediného řádku (flex-wrap: nowrap;), i kdyby se měly deformovat a smrštit.

.container {
  display: flex;
  flex-wrap: wrap; /* Pokud prvek nevejde, přeteče na nový řádek! */
}

Zkratka flex-flow: spojuje direction a wrap dohromady (např. flex-flow: row wrap;).

Zarovnávání na osách a moderní mezery (gap)

Dokonalá kontrola nad rozestupy a zarovnáním prvků bez nutnosti počítat záporné marginy.

1. justify-content (Hlavní osa)

Určuje rozprostření volného místa podél hlavní osy:

  • flex-start: Natlačí položky na začátek (výchozí).
  • center: Umístí všechny položky doprostřed.
  • flex-end: Natlačí položky na konec.
  • space-between: První prvek na začátku, poslední na konci, rovnoměrné mezery mezi nimi (skvělé pro navigace!).
  • space-around / space-evenly: Rovnoměrné mezery i kolem krajních prvků.

2. align-items (Příčná osa) & gap

Určuje zarovnání napříč podél příčné osy:

  • stretch: Roztáhne položky na celou výšku (výchozí).
  • center: Vycentruje svisle na střed (vertikální centrování!).
  • flex-start / flex-end: Zarovná k hornímu/dolnímu okraji.
Vlastnost gap: Konec margin trikům!
Zápis gap: 1.5rem; vytvoří mezeru výhradně mezi flex položkami. Nikdy nepřidá nechtěný okraj na vnější hrany kontejneru.

Pružnost položek: flex-grow, flex-shrink a flex-basis

Jak potomci reagují na přebytek či nedostatek místa v kontejneru.

Schopnost růst

flex-grow

Koeficient rozdělení zbývajícího volného místa.

  • Výchozí hodnota je 0 (prvek neroste, zachovává svou velikost).
  • Hodnota 1 znamená: „Rozdělte si zbývající volné místo rovným dílem“.
  • Má-li jeden prvek flex-grow: 2 a druhý 1, první získá dvojnásobek přebývajícího prostoru.
Schopnost smrštit se

flex-shrink

Ochota prvku zmenšit se, pokud je místa málo.

  • Výchozí hodnota je 1 (prvek se smrští, aby nepřetekl).
  • Hodnota 0 je extrémně důležitá v praxi: znamená přísný zákaz zmenšování (např. pro ikony či avatary, které se nesmí zploštit).
Výchozí rozměr & Shorthand

flex-basis a zkratka

Výchozí šířka před aplikací grow/shrink (např. 200px nebo auto).

/* Zkratka: grow shrink basis */
flex: 1 1 auto;   /* Plně pružný */
flex: 0 0 60px;  /* Pevný nerozbitný box */
flex: 1;         /* flex: 1 1 0% */

Interaktivní simulátor: Flexbox Playground

Vyzkoušejte si chování všech vlastností kontejneru i jednotlivých položek v reálném čase.

Vlastnosti kontejneru
Položka č. 1
.container { display: flex; }

  display: flex;
  gap: 16px;

3 zlaté šablony z reálného světa webdesignu

Běžné scénáře, které v praxi vyřešíte elegantně pomocí několika řádků Flexboxu.

1. Dokonalý střed

Vycentrování modálního okna nebo hrdinského nápisu přesně do středu obrazovky:

.hero-center {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

Super-trik: Uvnitř flex kontejneru stačí jedinému potomku nastavit margin: auto; a vystředí se v obou osách sám!

2. Navigační lišta

Logo vlevo a navigační odkazy vpravo se svislým zarovnáním na střed:

.navbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 1rem 2rem;
}

Shrnutí tématu a opakovací otázky

Ověřte si své znalosti pozicování, kontextu vrstvení a moderního rozvržení Flexbox.

01. Proč na prvku nefungují vlastnosti top, left ani z-index, když jsme mu žádnou pozici nenastavili?
Každý prvek má ve výchozím stavu position: static. V tomto režimu se řídí striktně běžným tokem dokumentu (Normal Flow) a prohlížeč jakékoliv souřadnice i vrstvení ignoruje. Pro jejich aktivaci musíte nastavit position na relative, absolute, fixed nebo sticky.
02. Vůči čemu se počítají souřadnice prvku s position: absolute?
Počítají se vůči nejbližšímu předkovi (rodiči), který má nastavené pozicování jiné než static (nejčastěji position: relative;). Pokud žádný takový předek v DOM stromu neexistuje, ukotví se prvek vůči počátečnímu vztažnému bloku (oknu prohlížeče).
03. Jaký je klíčový rozdíl mezi justify-content a align-items?
justify-content zarovnává prvky podél hlavní osy (při flex-direction: row vodorovně). align-items zarovnává prvky podél příčné osy (při row svisle). Pokud změníte flex-direction: column, role os se prohodí!
04. Co přesně způsobí nastavení flex-shrink: 0; na ikoně v seznamu?
Ve výchozím stavu mají flex položky flex-shrink: 1 (při nedostatku místa se zmenšují). Nastavením flex-shrink: 0 striktně zakážete jakékoliv smršťování – ikona si zachová svou přesnou velikost a nikdy nebude zploštěna dlouhým sousedním textem.
