Příběh vzniku webu: Tim Berners-Lee a CERN

Jak britský vědec vyřešil chaos v předávání vědeckých informací a stvořil základ celosvětové digitální společnosti.

CERN, březen 1989: Problém ztracených poznatků

V Evropské organizaci pro jaderný výzkum (CERN) ve Švýcarsku pracovaly tisíce fyziků z desítek zemí. Každý tým používal jiný počítač, jiný operační systém a odlišné formáty souborů. Dokumenty se ztrácely, když výzkumníci CERN opouštěli, a propojit související práce bylo téměř nemožné.

Tim Berners-Lee předložil návrh s názvem „Information Management: A Proposal“. Jeho nadřízený Mike Sendall si projekt přečetl a na titulní stranu připsal legendární poznámku: „Vague but exciting...“ (Nejasné, ale vzrušující...).

Klíčová myšlenka hypertextu: Text nemusí být lineární jako kniha. Kliknutím na vyznačené slovo (odkaz) se čtenář okamžitě přenese na jiný dokument kdekoliv na světě.

Tři pilíře, které Tim sestavil (1990)

  • HTML (Hypertext Markup Language): Formát pro popis struktury a odkazů.
  • HTTP (Hypertext Transfer Protocol): Protokol pro přenos hypertextu po síti TCP/IP.
  • URI / URL (Uniform Resource Identifier): Globálně unikátní adresní systém pro každý zdroj na světě.
Vánoce 1990: Na černém počítači NeXTcube běží první webový server a prohlížeč na světě. První webová adresa: http://info.cern.ch/hypertext/WWW/TheProject.html.
30. dubna 1993: CERN uvolnil technologii WWW jako public domain – bez licenčních poplatků, navždy otevřenou pro celé lidstvo.

Co je to Markup: Principy značkovacího jazyka

Značkovací jazyk není programovací jazyk. Jak se liší deklarace významu od algoritmického kódu a kde se vzala syntaxe.

Původ slova „Markup“

Pojem pochází z tradičního tiskařského průmyslu. Korektor v tiskárně vzal rukopis autora a červenou tužkou na okraje připisoval značky pro sazeče: „toto vysázej tučně“, „tady začni nový odstavec“ nebo „tento text je nadpis kapitoly“.

Značky přidávají surovému textu význam (sémantiku) a strukturu.

Značkovací vs. Programovací jazyk

HTML není programovací jazyk. Nemá cykly (for, while), podmínky (if/else), proměnné ani aritmetickou logiku.

Deklarativní přístup: V HTML píšeme CO dokument obsahuje, nikoli JAKÝM ALGORITMEM se má vypočítat.

Předchůdce SGML: Co to bylo?

SGML (Standard Generalized Markup Language, norma ISO 8879 z roku 1986) nebyl jeden jazyk, ale obrovský a složitý meta-jazyk – tedy jazyk sloužící k definování dalších značkovacích jazyků pomocí DTD (Document Type Definition).

Využití v armádě a letectví: SGML používalo americké ministerstvo obrany (US DoD) a letecké firmy (Boeing) pro správu statisíců stran technických manuálů ke stíhačkám na sálových počítačích.

Proč nemohlo být na webu? Plný SGML parser byl tak monstrózní a drahý, že by se nevešel do tehdejších osobních počítačů. Tim Berners-Lee proto z SGML vypreparoval pouhých 18 základních značek, přidal tag <a href="..."> pro hypertextový skok a stvořil HTML. Později v roce 1998 vzniklo XML jako 80% odlehčená podmnožka SGML pro univerzální výměnu dat.

Vývojové verze HTML, XML a slepá ulička XHTML

Cesta od 18 původních značek k modernímu living standardu a dramatický rozkol mezi W3C a konsorciem WHATWG.

Evoluce HTML verzí

1991 – HTML Tags: Pouhých 18 značek (z nichž 11 přežilo dodnes).
1995 – HTML 2.0 (RFC 1866): První oficiální standard IETF. Podpora formulářů.
1997 – HTML 3.2: Zavedení tabulek, appletů a obtékání textu kolem obrázků.
1999 – HTML 4.01: Zásadní milník na dalších 15 let. Oddělení obsahu od CSS stylů.
2014+ – HTML5 & Living Standard: WHATWG standard bez čísel verzí, neustále vyvíjený standard.

Krize XHTML 2.0 a drakonický XML parser

Kolem roku 2000 se W3C rozhodlo předělat HTML na striktní XHTML (Extensible Hypertext Markup Language) založené na XML pravidlech.

Fatal XML Error (Žlutá obrazovka smrti): Pokud v XHTML chybělo jediné lomítko nebo uvozovka, prohlížeč odmítl celou stránku vykreslit a zobrazil chybu parsování.

Vznik WHATWG (2004): Vývojáři prohlížečů (Apple, Mozilla, Opera) odmítli nepraktické XHTML 2.0, které by rozbilo existující weby. Založili pracovní skupinu WHATWG a definovali pragmatický přístup: Web musí fungovat pro lidi i při drobných chybách v kódu.

Anatomie HTML elementu: Tagy, atributy a obsah

Klikněte na jednotlivé části značky níže a prozkoumejte jejich přesnou syntaktickou roli.

Interaktivní rozklad značky (klikněte na prvek): <a href="..." target="...">Text</a>
<a href="https://skolavdf.cz" target="_blank"> Web SPŠ Varnsdorf </a>
Počáteční značka (Opening Tag)

Otevírá HTML element. Začíná ostrou závorkou < a končí >. Obsahuje název značky (zde a pro hypertextový odkaz) a volitelné atributy oddělené mezerou.

Párové elementy (Standardní)

Mají otevírací značku, vnitřní obsah a uzavírací značku s lomítkem </název>. 

<p>Odstavec textu</p>
<button>Odeslat</button>

Nepárové elementy (Void Elements)

Nemohou mít žádný vnitřní text ani potomky. Nemají koncovou značku. Lomítko na konci (/>) je v HTML5 volitelné. 

<img src="foto.webp" alt="Popis">
<input type="text"> <!-- <br>, <hr>, <meta>, <link> -->

Atributy HTML značek a pravidla zápisu

Jak předávat elementům dodatečné vlastnosti, identifikátory a konfiguraci.

Globální atributy

Lze je použít u libovolného HTML elementu:

  • id="main-nav": Unikátní identifikátor (max. 1× na stránce).
  • class="btn active": Třída pro CSS styly (může být opakovaná a vícenásobná).
  • title="...": Doplňkový tooltip po najetí myší.
  • lang="cs": Jazyk obsahu v daném elementu.
  • hidden: Skryje element z renderování i a11y.
  • tabindex="0": Řadí prvek do focus cyklu tabulátoru.

Pravidla zápisu & Boolean

Hodnoty píšeme vždy v rovných uvozovkách ("hodnota"):

Boolean atributy: Nemusí mít hodnotu! Jejich pouhá přítomnost zapíná stav true:
<input type="text" required disabled>
Zápisy disabled="true" nebo disabled="disabled" jsou zbytečné.

Vlastní data-* atributy

Umožňují uložit vlastní nestandardní data přímo k DOM prvku pro JavaScript: 

<div 
  data-user-id="4081"
  data-role="student">
</div>

V JS se čtou čistě přes element.dataset.userId.

Základní stavební kameny textu a obsahu

Nadpisy, odstavce, logické formátování textu a rozdíl mezi významem a pouhým vzhledem.

Hierarchie nadpisů <h1> až <h6>

Nadpisy tvoří logickou osnovu stránky (jako obsah v knize). Čtečky obrazovky podle nich umožňují nevidomým skákat po kapitolách. 

<h1>Hlavní nadpis stránky (pouze 1x na webu!)</h1>
  <h2>Kapitola 1: Historie</h2>
    <h3>Podsekce: Vynález hypertextu</h3>
  <h2>Kapitola 2: Současnost</h2>
Vykreslený výstup v prohlížeči (Render):
Hlavní nadpis stránky (h1)
Kapitola 1: Historie (h2)
Podsekce: Vynález hypertextu (h3)
Kapitola 2: Současnost (h2)
Chyba: Nikdy nepoužívejte h3 jen proto, že chcete menší písmo! Vzhled se řídí v CSS, nadpisy určují striktně význam.

Významové značky textu

V HTML vždy preferujeme sémantiku před prezentačními prvky:

<strong>Text</strong>: Silný důraz, varování (čtečka zvýší intonaci; vizuálně tučně).
<em>Text</em>: Zdůraznění v kontextu věty (vizuálně kurzíva).
<code> a <pre>: Počítačový kód a předformátovaný blok se zachováním mezer.
<blockquote>: Rozsáhlá citace z externího zdroje (atribut cite).
<br> vs <hr>: Zalomení řádku v básni vs tematický předěl mezi tématy.
Vykreslený výstup v prohlížeči (Render):

Ukázka silného důrazu strong a sémantického zvýraznění em v souvislém textu odstavce.

„Inovace rozlišuje mezi vůdcem a následovníkem.“
Příklad kódu: const web = "SPŠ";

Hypertextové odkazy: Značka <a> a typy cílů

Srdce World Wide Webu. Jak správně odkazovat na lokální soubory, externí servery a kotvy na stránce.

Absolutní vs. Relativní adresy

<!-- 1. Absolutní URL (externí web s protokolem) -->
<a href="https://w3.org/TR/html5/">W3C Standard</a>

<!-- 2. Relativní URL (soubor ve stejné složce) -->
<a href="kontakt.html">Kontakt</a>

<!-- 3. Relativní URL o úroveň výše (../) -->
<a href="../index.html">Zpět na katalog</a>

<!-- 4. Kotevní odkaz (skok na id elementu na stránce) -->
<a href="#kapitola-2">Přejít na kapitolu 2</a>
Vykreslený výstup v prohlížeči (Render):
W3C Standard ↗ • Kontakt • ← Zpět na katalog • # Přejít na kapitolu 2 ↓

Speciální protokoly a bezpečnost s target="_blank"

Odkazy umí přímo spouštět e-mailové klienty nebo vytáčet telefonní čísla na chytrých telefonech: 

<a href="mailto:skola@skolavdf.cz">Napsat e-mail</a>
<a href="tel:+420412371234">Zavolat na sekretariát</a>
Vykreslený výstup v prohlížeči (Render):
✉ Napsat e-mail ☎ Zavolat na sekretariát
Kritická bezpečnostní zranitelnost tabnabbing:
Při otevření nového okna přes target="_blank" má cizí stránka přístup k původnímu oknu přes window.opener. Vždy doplňujte:
rel="noopener noreferrer"

Seznamy v HTML: <ul>, <ol> a definiční <dl>

Strukturování výčtů položek, kroků v postupu a párování pojmů s jejich definicemi.

Nečíslovaný seznam <ul>

Unordered List pro položky, u kterých nezáleží na pořadí (nákupní seznam, vlastnosti, navigační menu). 

<ul>
  <li>HTML5</li>
  <li>CSS3</li>
  <li>JavaScript</li>
</ul>
Vykreslený výstup v prohlížeči:
  • HTML5
  • CSS3
  • JavaScript

Číslovaný seznam <ol>

Ordered List pro chronologické kroky a postupy. Podporuje atributy start="1" a reversed. 

<ol start="1">
  <li>Napiš HTML kód</li>
  <li>Zvaliduj dle W3C</li>
  <li>Nasaď na hosting</li>
</ol>
Vykreslený výstup v prohlížeči:
  1. Napiš HTML kód
  2. Zvaliduj dle W3C
  3. Nasaď na hosting

Definiční seznam <dl>

Páruje termíny (<dt>) s jejich popisy (<dd>). Skvělé pro slovníky pojmů a technické parametry. 

<dl>
  <dt>DNS</dt>
  <dd>Překlad jmen na IP.</dd>
  <dt>DOM</dt>
  <dd>Objektový strom stránky.</dd>
</dl>
Vykreslený výstup v prohlížeči:
DNS
Překlad jmen na IP.
DOM
Objektový strom stránky.

Minimální kostra dokumentu a hlavička <head>

Základní šablona každého validního webu, nastavení UTF-8, mobilní viewport a sociální metadata.

index.html — Standardní kostra HTML5 
<!DOCTYPE html>
<html lang="cs">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Výukový portál SPŠ</title>
  <meta name="description" content="Materiály pro studenty SPŠ.">
  
  <!-- Propojení stylopisu a ikony -->
  <link rel="stylesheet" href="style.css">
  <link rel="icon" href="favicon.svg" type="image/svg+xml">
</head>
<body>
  <h1>Vítejte ve světě webu!</h1>
  <p>První funkční stránka.</p>
</body>
</html>

Význam klíčových značek

<!DOCTYPE html> • Standards Mode vs. Quirks Mode:

V 90. letech měly prohlížeče (IE 4/5 a Netscape) vážné chyby v počítání rozměrů (box model počítal padding i border do width). Když W3C vytvořilo oficiální standard, prohlížeče zavedly tzv. DOCTYPE Sniffing:

  • Standards Mode: S <!DOCTYPE html> se stránka renderuje striktně dle moderních standardů W3C.
  • Quirks Mode („režim podivností“): Pokud DOCTYPE chybí, prohlížeč emuluje chyby z roku 1999 kvůli starým webům, což dnes okamžitě rozbije moderní layout a responzivitu!
html lang="cs": Oznámí prohlížeči a odečítači, že text je v češtině (správná výslovnost a dělení slov).
meta charset="UTF-8": Zajišťuje bezchybné zobrazení české diakritiky (ě, š, č, ř, ž, ý, á, í, é).
meta viewport: Bez tohoto řádku mobilní telefony zobrazí web jako zmenšenou desktopovou stránku a nepůjde responzivita.
Open Graph (og:title, og:image): Definuje obrázek a název náhledu při vložení odkazu na sociální sítě a Discord.

Shrnutí tématu • Základy jazyka HTML

Zopakujte si zásadní pravidla a otestujte své znalosti před přechodem na sémantický standard HTML5.

1

Proč se neujal standard XHTML 2.0 a jaký byl hlavní důvod vzniku iniciativy WHATWG?

XHTML 2.0 vyžadovalo drakonické parsování XML – jakákoliv drobná syntaktická chyba vedla k „pádu“ stránky na žlutou chybovou obrazovku (Yellow Screen of Death). Navíc nebylo zpětně kompatibilní se starým webem. Vývojáři prohlížečů (Apple, Mozilla, Opera) proto v roce 2004 založili WHATWG, aby vytvořili živý standard odolný vůči chybám se zpětnou kompatibilitou.
2

Jaký je rozdíl mezi párovým elementem a nepárovým (void elementem)? Uveďte 3 příklady void tagů.

Párový element ohraničuje text nebo další potomky pomocí otevírací a uzavírací značky (např. <p>text</p>). Void element nemůže mít žádný vnitřní obsah ani koncovou značku. Příklady: <img>, <br>, <hr>, <input>, <meta>, <link>.
3

Proč je nutné u odkazů s target="_blank" uvádět atribut rel="noopener noreferrer"?

Chrání před útokem zvaným reverse tabnabbing. Bez noopener má nově otevřená cizí stránka přístup k objektu window.opener vašeho okna a může na pozadí podstrčit falešnou přihlašovací stránku (phishing). noreferrer navíc zamezuje odeslání HTTP hlavičky Referer s původní URL.
4

K čemu slouží řádek <meta name="viewport" content="width=device-width, initial-scale=1.0">?

Přikazuje mobilnímu prohlížeči, aby nastavil šířku zobrazovací plochy (viewport) přesně podle fyzické šířky displeje zařízení v CSS pixelech s měřítkem 1:1. Bez tohoto metatagu by mobilní telefon předstíral rozlišení monitoru (cca 980 px) a celou stránku nečitelně zmenšil.
