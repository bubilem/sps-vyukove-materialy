Proč je přístupnost (a11y) klíčová pro každého vývojáře?

Přístupnost není laskavost pro malou skupinu lidí, ale základní kámen kvalitního webu a zákonný požadavek.

Zkratka a11y & Kdo ji potřebuje?

Slovo accessibility má mezi písmeny 'a' a 'y' přesně 11 písmen → odtud zkratka a11y.

  • Trvalá znevýhodnění: Nevidomí, slabozrací, neslyšící, lidé s motorickým třesem či ochrnutím.
  • Dočasná omezení: Zlomená dominantní ruka (ovládání pouze klávesnicí), rozbitá myš.
  • Situační vlivy: Ostré slunce svítící na displej mobilu, únava očí, hlučné prostředí.
Standard WCAG & Legislativa

Čtyři pilíře standardu POUR

  • Perceivable (Vnímatelný): Obsah musí být zřetelný (dostatečný kontrast, čtečka jej umí přečíst).
  • Operable (Ovladatelný): Veškeré ovládání musí fungovat z klávesnice bez myši.
  • Understandable (Srozumitelný): Jasné rozhraní a čitelná typografie.
  • Robust (Robustní): Kompatibilita s asistivními technologiemi.
Evropský zákon o přístupnosti (EAA) vyžaduje úroveň WCAG AA i pro komerční e-shopy a bankovnictví.

Kontrastní poměry barev: Pravidlo 4.5:1 a 3:1

Světle šedý text na bílém pozadí možná vypadá v grafickém editoru minimalisticky, ale v reálu je nečitelný.

Metrika kontrastního poměru

Kontrastní poměr vyjadřuje rozdíl v jasu mezi barvou popředí (textu) a barvou pozadí. Rozsah je od 1:1 (bílá na bílé) až po 21:1 (černá na bílé).

Běžný text (< 18pt / 24px):
Minimální požadovaný poměr je 4.5 : 1 pro úroveň AA (7:1 pro AAA).
Velký text (≥ 18pt nebo tučný ≥ 14pt):
Minimální požadovaný poměr je 3.0 : 1 pro úroveň AA.

Šedá #94a3b8 na bílé → Kontrast 2.5:1 (NEVYHOVUJE!)
Na slunci či pro seniora zcela neviditelné.
Tmavá #334155 na bílé → Kontrast 9.6:1 (VYNIKAJÍCÍ!)
Krásně čitelné za všech podmínek.

Hřích webdesignéra: Proč NIKDY nepsat outline: none?

Smazání rámečku focusu je jako odebrat řidiči volant: nevidí, kde se na stránce právě nachází.

Proč to kodéři dělali?

Grafikům se nelíbil výchozí modrý rámeček, který se v prohlížeči objevil po kliknutí myší na tlačítko. Kodéři proto často do CSS napsali: 

/* ZÁKAZ! Nejhorší řádek v historii CSS: */
*:focus {
  outline: none; /* Zničí navigaci z klávesnice! */
}

Jakmile uživatel odloží myš a začne stránku procházet klávesou Tab, netuší, na kterém tlačítku stojí. Web se stane zcela nepoužitelným.

Pravidlo: Pokud vypnout, vždy nahradit!

Nikdy neodstraňujte rámeček bez toho, abyste definovali vlastní, ještě hezčí a zřetelnější indikátor zaměření: 

.btn:focus {
  outline: 3px solid #2dd4bf;
  outline-offset: 3px; /* Odsazení od hrany */
}

Kouzelné řešení: Pseudotřída :focus-visible

Vlídný kompromis: rámeček se zobrazí pouze při navigaci klávesnicí, při kliknutí myší zůstane skrytý.

Chytrá heuristika prohlížeče

Moderní prohlížeče vědí, zda prvek získal focus kliknutím myši, nebo stiskem klávesy Tab na klávesnici: 

/* Zobrazí se POUZE při ovládání klávesnicí: */
button:focus-visible,
a:focus-visible {
  outline: 3px solid #2dd4bf;
  outline-offset: 2px;
  border-radius: 4px;
}
Spokojený grafik i handicapovaný uživatel
  • Uživatel myši: Klikne na tlačítko a nevidí žádný rušivý rámeček.
  • Uživatel klávesnice: Mačká klávesu Tab a okamžitě vidí výrazný kontrastní obrys aktivního prvku.
  • Dotykový displej: Ani při ťuknutí prstem se rámeček zbytečně neaktivuje.
V moderním CSS proto vždy stylovat :focus-visible místo holého :focus!

Čtečky obrazovek (Screen Readery) a třída .sr-only

Rozdíl mezi skutečným skrytím z DOMu a profesionálním skrytím pouze pro lidské oko.

display: none vs. a11y

Pokud prvku nastavíte display: none; nebo visibility: hidden;, prohlížeč jej zcela vymaže z asistenčního stromu.

Čtečka obrazovky prvek vůbec nepřečte! Nelze to tedy použít pro skrytí doplňkového popisku pro nevidomé.
Standardní třída .sr-only (Visually Hidden)

Prvek zabírá 1×1 pixel a je oříznut, takže není na obrazovce vidět, ale čtečka jej bez problémů přečte:

.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}

Využití: Ikona lupy na tlačítku vyhledávání → <button><svg>...</svg><span class="sr-only">Vyhledat</span></button>.

Zvětšování textu a respekt k nastavení: Proč psát v rem?

Slabozrací uživatelé si často v nastavení prohlížeče změní výchozí velikost písma z 16 px na 24 px.

Problém pevného pixelu (px)

Pokud nastavíte font-size: 16px; natvrdo v pixelech, prohlížeč přebije volbu uživatele. Senior se slabším zrakem bude mít text stále miniaturní. 

/* Špatně pro a11y: */
body { font-size: 16px; }
Síla relativní jednotky rem

Jednotka 1rem vychází z velikosti nastavené uživatelem v kořeni dokumentu: 

/* Správně: respektuje volbu v prohlížeči */
body { font-size: 1rem; }
h1   { font-size: 2rem; }

Když si uživatel zvětší výchozí písmo, celá stránka se proporcionálně a čitelně zvětší.

Barvoslepost (Daltonismus): Nepřenášejte význam pouze barvou

Přibližně 8 % mužů a 0,5 % žen má vadu barvocitu. Zelená a červená jim často splývají v jeden odstín hnědé.

Špatný přístup: Pouze červený rámeček

Pokud při chybě ve formuláři pouze obarvíte rámeček na červeno, člověk s protanopií nebo deuteranopií nepozná, co je špatně.

E-mail: [ neplatný_mail ]
Správný přístup: Barva + Ikona + Text

Ke změně barvy vždy přidejte zřetelnou ikonu (např. vykřičník) a textové vysvětlení chyby:

E-mail: [ neplatný_mail ]
Zadejte prosím platnou e-mailovou adresu.

Dotykové cíle (Touch Targets) a šetření pohybu

Respekt k motorickým schopnostem prstů na dotykových displejích a ochrana před kinetózou.

Minimální plocha: 44 × 44 px

Podle specifikace WCAG musí mít každý interaktivní prvek (tlačítko, odkaz v menu) rozměr dotykové plochy minimálně 44×44 pixelů. 

.nav-link {
  display: inline-flex;
  align-items: center;
  min-height: 44px;
  padding: 0.5rem 1rem;
}

Ztlumení animací (prefers-reduced-motion)

Divoké zoomování a rotace mohou vyvolat nevolnost. Respektujte systémové nastavení uživatele: 

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Kontrolní checklist přístupného CSS před nasazením

Rychlá kontrola, kterou by měl projít každý web před odevzdáním nebo publikací.

  • Focus viditelný: Web lze plnohodnotně projít pouze pomocí klávesy Tab, focus je vždy zřetelný (:focus-visible).
  • Kontrast textu: Běžný text má kontrast alespoň 4.5:1 vůči pozadí (ověřeno v Lighthouse nebo Colour Contrast Analyser).
  • Relativní jednotky: Velikost písma a klíčové rozestupy jsou v rem, ne v pevných px.
  • Dotykové plochy: Tlačítka a odkazy na mobilu mají rozměr alespoň 44×44 pixelů.
  • Čtečky obrazovek: Doplňkové popisky pro ikony používají třídu .sr-only, nikoliv display: none.
  • Prezenční animace: Kód obsahuje @media (prefers-reduced-motion) pro potlačení agresivních efektů.

Shrnutí tématu a opakovací otázky

Ověřte si své porozumění webové přístupnosti, kontrastu, stavům focusu a čtečkám obrazovek.

01. Proč je zápis outline: none bez náhrady považován za zásadní chybu?
Odstraní vizuální indikátor focusu. Uživatelé, kteří ovládají web pomocí klávesnice (klávesa Tab), nevidí, který prvek je právě aktivní, a web se pro ně stane zcela neovladatelným. Místo toho máme stylovat pseudotřídu :focus-visible.
02. Jaký je minimální kontrastní poměr pro běžný text podle standardu WCAG AA?
Pro běžný text je minimální poměr 4.5 : 1. Pro velký text (≥ 24 px nebo tučný ≥ 18.5 px) je požadováno minimum 3.0 : 1.
03. Proč pro skrytí textu pro čtečky obrazovek nesmíme použít display: none?
Vlastnost display: none odstraní element nejen z vizuálního zobrazení, ale i z asistenčního stromu (Accessibility Tree). Čtečka obrazovky jej proto úplně přeskočí. Pro skrytí výhradně zraku používáme techniku .sr-only.
04. K čemu slouží pravidlo @media (prefers-reduced-motion: reduce)?
Detekuje, zda má uživatel v operačním systému zapnuté omezení animací. Slouží k ochraně lidí trpících vestibulárními poruchami, kinetózou nebo epilepsií tím, že okamžitě vypne nebo ztlumí rotace, posuny a blikající efekty.
