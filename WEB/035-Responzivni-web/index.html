Responzivní web a Media queries

Jeden univerzální kód pro všechna moderní zařízení • Od viewport meta tagu a filozofie Mobile-First přes syntaxi @media dotazů, standardní zlomové body (breakpointy), detekci Dark mode přes prefers-color-scheme až po moderní Container queries.

Viewport Meta Tag

Správné měřítko 1:1 na mobilních displejích bez simulace miniaturního desktopu.

Mobile-First přístup

Stavba od nejmenších displejů s min-width pravidly pro čistší a rychlejší kód.

Breakpointy & Media

Zlomové body 640px, 768px, 1024px a 1280px dle přirozených potřeb obsahu.

Dark Mode & @container

Detekce preferencí uživatele a zlomové body řízené velikostí komponenty.

Klíčový základ: <meta name="viewport">

Proč je tento jediný řádek v hlavičce <head> naprosto nezbytný pro každý moderní web.

Povinný kód v každém HTML5 dokumentu 
<meta name="viewport" 
      content="width=device-width, initial-scale=1.0">
  • width=device-width: Nastaví šířku průzoru stránky přesně na fyzickou logickou šířku displeje mobilu (např. 390px místo 980px).
  • initial-scale=1.0: Nastaví výchozí měřítko přiblížení na 1:1 bez umělého oddálení.

Co se stane, když tag chybí?

Mobilní prohlížeče (Safari, Chrome) předpokládají, že web vznikl v 90. letech. Zobrazí stránku na virtuální šířce 980 pixelů a celou ji zmenší tak, aby se vešla na displej.

Důsledek: Písmo je mikroskopické, tlačítka nelze trefit prstem a veškeré vaše Media queries v CSS jsou na mobilu zcela ignorovány!

Filozofie Mobile-First vs. Desktop-First

Proč profesionální vývojáři píší kód nejdříve pro nejmenší displeje a postupně přidávají vlastnosti.

1. Mobile-First (Moderní standard)

  • Výchozí CSS kód (bez @media) je psán pro mobilní telefony (jednoduchý tok, 1 sloupec).
  • Pomocí @media (min-width: ...) postupně přidáváme další sloupce a efekty pro větší obrazovky.
  • Výhody: Mobil stahuje minimum CSS a nic nemusí přepisovat. Kód je čistší a web načítá bleskově.
.grid { grid-template-columns: 1fr; } /* Mobil */
@media (min-width: 768px) {
  .grid { grid-template-columns: repeat(2, 1fr); } /* Tablet */
}

2. Desktop-First (Zastaralý přístup)

  • Začíná se složitým 4sloupcovým layoutem pro velký monitor.
  • Následně pomocí @media (max-width: ...) kodér pracně vypíná, maže a přepisuje vlastnosti, aby se obsah vešel na mobil.
  • Nevýhody: Zbytečně bobtnající CSS, časté chyby v kaskádě a pomalejší mobilní výkon.

Syntaxe pravidel @media: Klasika vs. Moderní rozsah

Jak psát podmínky pro rozlišení displeje a jaká je nová, mnohem čitelnější syntaxe.

Tradiční zápis (Media Queries Level 3)

Využívá klíčová slova min-width a max-width spojená operátorem and:

/* Od šířky 768px a více: */
@media screen and (min-width: 768px) {
  body { font-size: 18px; }
}

/* V rozmezí mezi 600px a 1024px: */
@media (min-width: 600px) and (max-width: 1024px) { ... }
Moderní zápis rozsahů (Media Queries Level 4)

Podporováno ve všech moderních prohlížečích. Využívá přirozené matematické operátory >=, <=:

/* Mnohem čitelnější zápis: */
@media (width >= 768px) {
  body { font-size: 18px; }
}

/* Rozsah jako v matematice: */
@media (600px <= width <= 1024px) { ... }

Strategie zlomových bodů (Breakpointů)

Nestavte breakpointy pro konkrétní modely iPhonů, ale pro přirozený zlom vašeho obsahu.

Průmyslový standard zlomů
< 640 px: Mobilní telefony 1 sloupec
640 px – 767 px: Velké mobily / Phablety 1–2 sloupce
768 px – 1023 px: Tablety na výšku 2–3 sloupce
1024 px – 1279 px: Notebooky / Tablety na šířku 3–4 sloupce
>= 1280 px: Stolní monitory Plný layout + max-width
Zlaté pravidlo obsahu

Breakpoint určuje obsah, ne zařízení

Každý rok přibývají desítky nových displejů s různým rozlišením. Kdy tedy přidat nový breakpoint?

Test tažením okna: Zmenšujte okno prohlížeče v DevTools. Přesně v momentě, kdy se text nepěkně zlomí, tlačítka se dotknou nebo menu začne přetékat, přidejte breakpoint!

Pružná multimédia: Obrázky a videa, která nepřetečou

Jak zajistit, aby fotografie a vložená YouTube videa nerozbily mobilní layout.

Pružné obrázky (Fluid Images)

Do globálního CSS resetu vždy patří:

img, picture, video {
  max-width: 100%;
  height: auto;
  display: block;
}
  • max-width: 100% zajistí, že se obrázek zmenší, pokud je rodič užší než jeho rozlišení.
  • height: auto zachová správný poměr stran a zabrání deformaci (zploštění).

Videa a moderní aspect-ratio

Dříve bylo nutné pro responzivní <iframe> s videem používat složité padding triky. Dnes máme nativní vlastnost:

iframe.youtube-video {
  width: 100%;
  aspect-ratio: 16 / 9;
  border: none;
}

Prohlížeč automaticky dopočítává výšku videa podle aktuální šířky tak, aby poměr stran zůstal přesně 16:9.

Uživatelské preference: prefers-color-scheme (Dark Mode)

Respektujte nastavení operačního systému uživatele a nabídněte tmavý motiv bez jediného řádku JavaScriptu.

Nativní reakce na systémový motiv

Pokud má uživatel v systému Windows, macOS, Androidu či iOS zapnutý tmavý režim, prohlížeč tuto hodnotu předá do CSS: 

/* Výchozí světlý motiv: */
:root {
  --bg-color: #ffffff;
  --text-color: #0f172a;
}

/* Automatické přepnutí na tmavý motiv: */
@media (prefers-color-scheme: dark) {
  :root {
    --bg-color: #0f172a;
    --text-color: #f8fafc;
  }
}
Kombinace s CSS proměnnými

Proč je to tak geniální?

  • Nemusíte psát duplicitní kód pro desítky různých tlačítek, karet a odkazů.
  • V media query změníte pouze hodnoty CSS proměnných na :root a celý web se okamžitě přebarví!
  • Šetří zrak uživatelů v noci a snižuje spotřebu baterie na OLED displejích mobilních telefonů.

Přístupnost v Media Queries: prefers-reduced-motion

Ochrana zdraví uživatelů s kinetózou, vestibulárními poruchami nebo pomalým internetem.

Ochrana zdraví uživatelů

prefers-reduced-motion

Rychlé posuny, rotace a paralaxní efekty mohou u některých lidí vyvolat závratě nebo nevolnost. Pokud v systému zvolili omezení pohybu: 

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
Šetření dat a tisk

prefers-reduced-data a @media print

  • @media (prefers-reduced-data: reduce): Uživatel má aktivovaný režim šetření dat. Můžete vypnout velké obrázky na pozadí a omezit stahování webfontů.
  • @media print: Styl pro tisk dokumentu (skryje menu a reklamy, nastaví bílé pozadí a černý text).

Budoucnost responzivity: Kontejnerové dotazy (@container)

Konec závislosti na šířce celého okna: komponenta se přizpůsobuje prostoru, ve kterém se nachází.

Problém klasických Media Queries

Pravidlo @media se vždy ptá na velikost celého okna prohlížeče. Co když ale tutéž kartu produktu vložíte jednou do širokého hlavního sloupce a podruhé do úzkého sidebaru?

Na velkém displeji by karta v úzkém sidebaru přetekla, protože okno je sice široké, ale její rodič má jen 200px!
Řešení: @container queries 
/* 1. Označíme rodiče jako sledovaný kontejner: */
.card-wrapper {
  container-type: inline-size;
}

/* 2. Karta reaguje na šířku svého obalu: */
@container (min-width: 450px) {
  .card {
    display: flex;
    flex-direction: row; /* Foto vedle textu */
  }
}

3 nejčastější hříchy začátečníků v responzivním designu

Na co si dát pozor při testování a odevzdávání studentských projektů.

1. Pevné šířky v pixelech

Zápis width: 500px; způsobí na mobilu o šířce 390px okamžitou katastrofu.

Správné řešení: Vždy použijte max-width: 500px; width: 100%;. Na velkém monitoru má box 500px, na mobilu se bezpečně smrští.

2. Horizontální scrollbar

Pokud se na mobilu stránka „kýve“ do stran, nějaký prvek (obrázek, tabulka nebo nepřirozený margin) přetekl ven.

Správné řešení: Zkontrolujte, zda mají všechny obrázky max-width: 100% a zda nemáte pevnou šířku na vnějším kontejneru.

3. Malé dotykové plochy

Na desktopu má myš přesnost 1 pixelu. Na mobilu má lidský palec průměr cca 10 mm (44×44 pixelů).

Správné řešení: Tlačítka a odkazy na mobilu musejí mít dostatečný padding (min. velikost dotykového terče 44×44 px).

Shrnutí tématu a opakovací otázky

Ověřte si své znalosti Media Queries, Mobile-First principu a responzivních multimédií.

01. Proč je v HTML nezbytný meta tag <meta name="viewport" content="width=device-width, initial-scale=1.0">?
Bez tohoto tagu mobilní prohlížeč předpokládá starý desktopový web, vykreslí stránku na virtuální šířce 980 pixelů a celou ji zmenší na nečitelné měřítko. Teprve s tímto tagem prohlížeč přizpůsobí šířku skutečnému displeji a začne správně vyhodnocovat Media queries.
02. V čem spočívá hlavní výhoda přístupu Mobile-First oproti Desktop-First?
Při Mobile-First píšeme základní CSS pro nejslabší zařízení bez jakéhokoliv @media pravidla. Větší obrazovky pak pouze doplňují nové sloupce pomocí min-width. Mobilní telefon tak nemusí stahovat a přepisovat složité desktopové layouty, což dramaticky urychluje načítání webu.
03. Jak funguje pravidlo @media (prefers-color-scheme: dark)?
Dotazuje se na systémové nastavení uživatele (zda má v operačním systému aktivní tmavý motiv). Pokud ano, prohlížeč automaticky aplikuje pravidla uvnitř tohoto bloku – typicky stačí předefinovat hodnoty CSS proměnných pro pozadí a text na :root. Funguje zcela bez JavaScriptu.
04. Jaký je zásadní rozdíl mezi Media Queries a novými Container Queries?
Media Queries testují šířku celého okna prohlížeče (viewportu). Container Queries (@container) umožňují komponentě reagovat na šířku jejího konkrétního rodičovského obalu. Komponenta tak může změnit svůj vzhled i tehdy, když je vložena do úzkého postranního panelu na širokém monitoru.
