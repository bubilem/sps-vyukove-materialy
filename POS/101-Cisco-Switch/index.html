Scénář • Krok 1

Krok 1: Identita, varovný banner MOTD a vypnutí DNS

Prvním krokem konfigurace je jednoznačná identifikace přepínače, nastavení právního upozornění a zamezení zasekávání CLI.

Příkazy v režimu Global Config 

Switch> enable
Switch# configure terminal
Switch(config)# hostname SW-PATER-01
SW-PATER-01(config)# no ip domain-lookup
SW-PATER-01(config)# banner motd #ZAKAZ NEOPRAVNENEHO PRISTUPU!#
  • hostname: Změní prompt terminálu – správce má okamžitou jistotu, kde se nachází.
  • no ip domain-lookup: Pokud uděláte v CLI překlep (např. enabble), IOS se standardně pokouší přeložit toto slovo přes DNS na IP adresu a terminál na 2 minuty zamrzne! Tento příkaz to zcela eliminuje.

Didaktický rozbor: Právní význam MOTD banneru

Banner MOTD (Message of the Day) se zobrazí každému uživateli ještě před přihlášením.

ZÁSADNÍ CHYBA: Nikdy nepište slovo "Vítejte" (Welcome)!
V mezinárodním i českém právu může útočník u soudu argumentovat, že systém jej sám „přivítal“ (Welcome). Správný banner musí striktně varovat: „Pouze pro autorizovaný personál. Neoprávněný přístup je monitorován a trestně stíhán.“

Znak # na začátku a na konci funguje jako oddělovač (delimiting character), který IOSu říká, kde text banneru končí.

Scénář • Krok 2

Krok 2: Ochrana priviligovaného režimu (Enable Secret)

Kdo získá přístup do privilegovaného režimu (#), má absolutní moc nad zařízením. Proto musí být tento přechod chráněn silným kryptografickým hashem.

Příkaz enable secret 

SW-PATER-01(config)# enable secret SuperTajneHeslo123!

Tento příkaz nastaví heslo pro příkaz enable. Heslo se do konfigurace neukládá jako čitelný text, nýbrž se okamžitě jednosměrně zahešuje (MD5 Type 5 hash nebo novější SHA-256 scrypt Type 8/9).

Proč NIKDY nepoužívat "enable password"?

Vlastnost enable password (ZASTARALÉ) enable secret (SPRÁVNÉ)
Uložení v souboru: Čistý čitelný text (Plaintext) Kryptografický hash
Příklad v show run: enable password cisco enable secret 5 $1$mERr$hx5r...
Priorita v IOS: Nižší (ignoruje se) Vždy má přednost!

Pokud v konfiguraci zadáte oba příkazy, Cisco IOS automaticky použije bezpečnější enable secret a enable password ignoruje.

Scénář • Krok 3

Krok 3: Zabezpečení fyzické konzole (Line Console 0)

Fyzický konzolový port na switchi nesmí zůstat otevřený. Pokud by někdo v racku připojil modrý rollover kabel, switch musí okamžitě vyžadovat přihlašovací heslo.

Konfigurace linky Line Console 0 

SW-PATER-01(config)# line console 0
SW-PATER-01(config-line)# password CiscoKonzole123!
SW-PATER-01(config-line)# login
SW-PATER-01(config-line)# logging synchronous
SW-PATER-01(config-line)# exec-timeout 5 0
SW-PATER-01(config-line)# exit

Rozbor jednotlivých příkazů linky

  • password <heslo>: Nastaví heslo, které bude vyžadováno při fyzickém připojení přes sériový kabel.
  • login: ZÁSADNÍ PŘÍKAZ! Bez příkazu login se zadané heslo vůbec neaktivuje a konzole se dál neptá na nic!
  • logging synchronous: Zabraňuje systémovým zprávám (např. %LINK-3-UPDOWN), aby vám rozbily rozepsaný příkaz. Po výpisu hlášky IOS automaticky znovu vypíše váš rozepsaný řádek!
  • exec-timeout 5 0: Bezpečnostní časovač nečinnosti: automaticky odhlásí terminál po 5 minutách a 0 sekundách bez aktivity.
Scénář • Krok 4

Krok 4: Globální šifrování hesel (service password-encryption)

Heslo pro konzoli a hesla pro linky VTY jsou v souboru running-config standardně uložena v čistém textu. Kdokoli se vám podívá přes rameno (shoulder surfing), heslo ihned uvidí.

Aktivace služby šifrování 

SW-PATER-01(config)# service password-encryption

Tento jediný globální příkaz okamžitě převede všechna nezašifrovaná hesla v konfiguraci (pro konzoli, VTY i zastaralý enable password) na zašifrovaný tvar Cisco Type 7. 

! V konfiguraci po aktivaci:
line con 0
 password 7 0822455D0A16
 login

Odborné varování SPŠ: Šifra Type 7 NENÍ bezpečná!

Algoritmus Type 7 je pouze jednoduchá Vigenèrova reverzibilní šifra (obfuskace) vytvořená v 80. letech minulého století.

  • Kdokoli, kdo získá text konfiguračního souboru (např. ze zálohy), dokáže heslo Type 7 dešifrovat za zlomek sekundy pomocí bezplatných online nástrojů.
  • Účelem service password-encryption je pouze ochrana před náhodným pohledem na monitor v učebně či serverovně.
  • Pro skutečné zabezpečení vždy používejte enable secret a pro uživatelské účty parametr secret namísto password!
Vzdálená správa • Bezpečnost

Krok 5: Vzdálená správa – Proč je Telnet zakázán a jak nastavit SSH

Vzdálená správa přes síť je nutností, protože správce nesedí u switche s kabelem. Protokol Telnet je však v moderních sítích přísně zakázán – nahrazuje jej SSH v2.

Telnet (TCP port 23) – ZAKÁZÁNO

Přenáší veškerá data, přihlašovací jména a hesla v otevřeném nešifrovaném textu (Cleartext).

[Wireshark Packet #142]
Telnet Data: Username: admin
Telnet Data: Password: MojeTajneHeslo123
Útočník s Wiresharkem na síti ihned vidí vaše hesla!

SSH verze 2 (TCP port 22) – STANDARD

Využívá silnou asymetrickou kryptografii (RSA) a symetrické šifrování celého datového toku (AES).

[Wireshark Packet #142]
SSHv2 Encrypted Packet: 7f8a 9c2b 1e4f ...
Payload: Nerozluštitelný binární šum
Hesla ani příkazy nelze odposlechnout ani pozměnit.

Čtyři podmínky pro aktivaci SSH na Cisco switchi:

SW-PATER-01(config)# ip domain-name sps-skola.cz             ! 1. Doména je nutná pro výpočet FQDN klíče
SW-PATER-01(config)# crypto key generate rsa modulus 2048    ! 2. Vygenerování 2048-bitového páru RSA klíčů
SW-PATER-01(config)# ip ssh version 2                        ! 3. Vynucení moderní bezpečné verze SSH 2
SW-PATER-01(config)# username admin privilege 15 secret SpravcePass2026!  ! 4. Vytvoření lokálního správce
Scénář • Krok 6

Krok 6: Konfigurace virtuálních terminálů (Line VTY 0 15)

Linky VTY (Virtual Teletype) představují virtuální relace pro vzdálené připojení k přepínači po síti. Switch Catalyst 2960 disponuje 16 linkami (0 až 15).

Konfigurace linek pro výhradní použití SSH 

SW-PATER-01(config)# line vty 0 15
SW-PATER-01(config-line)# transport input ssh
SW-PATER-01(config-line)# login local
SW-PATER-01(config-line)# exec-timeout 10 0
SW-PATER-01(config-line)# logging synchronous
SW-PATER-01(config-line)# exit

Klíčové bezpečnostní mechanismy VTY

  • transport input ssh:
    Přísně zakáže nezabezpečený Telnet! Switch bude na portu 22 přijímat pouze šifrovaná spojení protokolu SSH.
  • login local:
    Přepínač nebude vyžadovat jedno společné heslo pro všechny, ale ověří uživatele proti lokální databázi účtů vytvořené příkazem username admin secret .... Každý správce tak může mít svůj vlastní účet!
  • exec-timeout 10 0:
    Pokud vzdálený správce zapomene otevřené okno PuTTY a odejde na oběd, switch relaci po 10 minutách automaticky zavře.
Síťová vrstva • IP konfigurace

Krok 7: Management rozhraní switche (SVI – VLAN 1)

Klasický L2 přepínač nemá na fyzických portech IP adresy – fyzické porty pracují pouze s rámci a MAC adresami. Jak tedy switch může komunikovat přes IP s administrátorem?

Co je to SVI (Switched Virtual Interface)?

SVI je logické virtuální rozhraní vytvořené uvnitř switche navázané na virtuální síť VLAN. Umožňuje přiřadit přepínači vlastní IP adresu pro vzdálenou správu. 

SW-PATER-01(config)# interface vlan 1
SW-PATER-01(config-if)# ip address 192.168.10.2 255.255.255.0
SW-PATER-01(config-if)# description SPRAVCOVSKE ROZHRANI SVI
SW-PATER-01(config-if)# no shutdown
SW-PATER-01(config-if)# exit

Proč je nutný příkaz "no shutdown"?

Ve výchozím továrním nastavení je virtuální rozhraní interface vlan 1 v administrativně vypnutém stavu (administratively down).

  • Bez zadání příkazu no shutdown zůstane rozhraní neaktivní a na přidělenou IP adresu se nebude možné připojit ani pingnout!
  • Podmínka stavu UP: Aby rozhraní vlan 1 přešlo do stavu Up/Up, musí být alespoň jeden fyzický port patřící do VLAN 1 aktivně připojen kabelem k zapnutému zařízení (PC nebo router).
Směrování • Dostupnost

Krok 8: Nastavení výchozí brány (ip default-gateway)

Častá záludná otázka u zkoušek: „Proč potřebuje L2 switch výchozí bránu, když sám žádné pakety nesměruje?“

Příkaz v režimu Global Config 

SW-PATER-01(config)# ip default-gateway 192.168.10.1

Příkaz nastavuje IP adresu směrovače (routeru), který propojuje místní síť s okolním světem (školní páteří, internetem nebo VPN).

Didaktický rozbor: Kdy switch bránu použije?

  • Pokud je správce připojen kabelem ve stejné podsíti (např. PC má IP 192.168.10.50), komunikace probíhá přímo na L2 vrstvě přes MAC adresy – brána není potřeba.
  • Pokud se však správce připojuje z jiné učebny, z domova přes VPN nebo ze školního serveru (např. IP 10.0.5.20), switch musí své odpovědi odeslat na směrovač (Gateway)!
  • Bez nastaveného ip default-gateway switch sice paket z jiné sítě přijme, ale nedokáže odpovědět zpět – SSH spojení z jiné sítě okamžitě zhavaruje na timeout!
Fyzické porty • Zabezpečení

Krok 9: Konfigurace fyzických portů a bezpečnostní vypnutí

Správce musí udržovat pořádek v dokumentaci portů a dodržovat základní bezpečnostní zásadu: nepoužívané porty nesmí být aktivní.

Konfigurace aktivního portu pro PC 

SW-PATER-01(config)# interface FastEthernet0/1
SW-PATER-01(config-if)# description PC-UCITEL-KATEDRA
SW-PATER-01(config-if)# switchport mode access
SW-PATER-01(config-if)# duplex full
SW-PATER-01(config-if)# speed auto
SW-PATER-01(config-if)# exit
  • description: Zásadní pro přehlednost při řešení problémů v show interfaces.
  • switchport mode access: Port je vyhrazen pro koncovou stanici (nikoli pro trunk propojení na další switch).

Zlaté bezpečnostní pravidlo: Vypnout nepoužité porty!

Pokud máte 24portový switch a zapojeno je pouze 8 počítačů, zbylých 16 portů musíte vypnout, aby se do nich nikdo nepovolaný nezapojil! 

SW-PATER-01(config)# interface range FastEthernet0/9 - 24
SW-PATER-01(config-if-range)# description NEPOUZIVANE PORTY
SW-PATER-01(config-if-range)# shutdown
SW-PATER-01(config-if-range)# exit
Příkaz interface range umožňuje nakonfigurovat desítky portů najednou jediným příkazem!

Krok 10: Uložení konfigurace a ověření stavu (Verifikace)

Konfigurace je hotová. Nyní zbývá zkontrolovat funkčnost klíčovými příkazy a trvale uložit výsledky do paměti NVRAM.

Uložení do NVRAM (copy run start) 

SW-PATER-01# copy running-config startup-config
Destination filename [startup-config]? Enter
Building configuration...
[OK]

Pokud tento krok vynecháte, při nejbližším výpadku elektrického proudu nebo restartu se switch vrátí do čistého továrního stavu a veškerá práce bude ztracena!

5 Klíčových verifikačních příkazů

  • show ip interface brief:
    Ověří, zda je Vlan1 ve stavu up / up se správnou IP adresou.
  • show ip default-gateway:
    Zobrazí nastavenou výchozí bránu pro vzdálenou správu.
  • show ip ssh:
    Potvrdí, zda je aktivní SSH Enabled - version 2.0.
  • show running-config:
    Kompletní kontrola zašifrovaných hesel, VTY linek a portů.
  • show mac address-table:
    Zobrazí naučené MAC adresy připojených zařízení na jednotlivých portech.

Ověření znalostí

Opakovací otázky: Prověřte své znalosti konfigurace switche

Klikněte na tlačítko u otázky a ověřte si své porozumění konfiguraci a zabezpečení Cisco přepínačů.

1 Proč se na linkách Line VTY nastavuje "transport input ssh" a jaký je bezpečnostní důsledek?
Příkaz transport input ssh na linkách line vty 0 15 striktně povolí pouze šifrovaný protokol SSH a zcela zakáže nezabezpečený Telnet. Zabraňuje tomu, aby útočník odposlouchával přihlašovací jména a hesla správce v otevřeném textu na síti.
2 Jaký je rozdíl mezi "enable password" a "enable secret" a co dělá příkaz "service password-encryption"?
enable secret ukládá heslo jako bezpečný jednosměrný kryptografický hash (MD5/SHA-256 scrypt) a má vždy přednost. Zastaralý enable password ukládá heslo v čistém textu. Příkaz service password-encryption zašifruje všechna hesla v konfiguraci pomocí lehké obfuskace Type 7 (ochrana před pohledem přes rameno).
3 Co je to rozhraní SVI a proč nestačí IP adresu nastavit na fyzický port např. FastEthernet 0/1?
L2 přepínač nemá fyzické IP porty – fyzické porty pracují na 2. vrstvě s MAC adresami. Aby měl switch IP adresu pro vzdálenou správu (SSH/ping), vytváří se virtuální rozhraní SVI (Switched Virtual Interface) interface vlan 1, na které se přiřadí IP adresa a aktivuje se příkazem no shutdown.
4 Proč je nutné na switchi nastavit příkaz "ip default-gateway", i když switch sám o sobě nesměruje provoz klientů?
Výchozí brána (Default Gateway) umožňuje samotnému operačnímu systému switche odesílat odpovědi klientům, kteří se k němu připojují z jiné podsítě (např. správce přistupující přes router ze vzdálené učebny, internetu nebo VPN). Bez brány by switch nedokázal odpovědět na SSH dotazy mimo svou lokální síť.
