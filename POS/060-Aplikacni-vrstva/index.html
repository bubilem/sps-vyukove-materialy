Aplikační vrstva (Application Layer)

Vrstvová architektura

Zařazení aplikační vrstvy: Rozdíl mezi OSI a TCP/IP

V 7vrstvém modelu ISO/OSI je vrchol rozdělen do tří samostatných úrovní. V praktickém modelu TCP/IP jsou všechny sloučeny do jediné aplikační vrstvy.

Dekompozice v modelu ISO/OSI (L5 až L7)

Vrstva 7: Aplikační (Application)
Poskytuje rozhraní přímo koncovým uživatelským aplikacím (HTTP, DNS, SSH, FTP).
L7
Vrstva 6: Prezentační (Presentation)
Formátování, syntaxe dat, kódování znaků (UTF-8, ASCII), komprese (Gzip) a šifrování (TLS).
L6
Vrstva 5: Relační (Session)
Zakládá, řídí, synchronizuje a ukončuje dialogy/relace mezi dvěma aplikacemi.
L5

Pragmatický přístup modelu TCP/IP

V reálném softwaru a v modelu TCP/IP jsou všechny tyto tři funkce integrovány přímo do konkrétního aplikačního protokolu a knihoven programu:

  • Například webový prohlížeč s HTTPS: Řeší aplikační dotaz (GET /index.html – L7), šifrování a certifikáty TLS (L6) i udržování přihlašovací relace a cookies (L5) v rámci jediného procesu.
  • Jednoduchost a rychlost: Odpadá zbytečná mezivrstvová režie a programátor má plnou kontrolu nad formátem zpráv.
Funkce L7

Účel a klíčové úkoly aplikační vrstvy

Aplikační vrstva nepopisuje samotné grafické okno programu (např. tlačítka v Chrome), ale protokoly, kterými program formuluje požadavky a vyměňuje zprávy po síti.

1. Definice syntaxe

Určuje přesnou strukturu zpráv – příkazy (GET, POST), hlavičky, oddělovače řádků a formát odpovědí (např. JSON, XML, HTML).

2. Šifrování a TLS

Ochrana dat před odposlechem. Zajišťuje důvěrnost a ověření identity serveru pomocí kryptografických certifikátů.

3. Komprese dat

Zmenšení objemu přenášených dat (algoritmy Gzip, Brotli, JPEG) pro zrychlení načítání a úsporu šířky pásma v síti.

4. Autentizace

Ověření identity uživatele a přístupových práv (přihlašovací údaje, tokeny OAuth2, SSH klíče, API klíče).

Aplikační modely

Architektury síťových aplikací: Klient-Server vs. P2P

Způsob, jakým spolu komunikující uzly spolupracují, určuje celkovou spolehlivost, bezpečnost i škálovatelnost celého řešení.

Model Klient-Server (Client-Server)

Centralizovaný model s jasně vymezenými rolemi. Server má pevnou IP adresu, běží nepřetržitě a pasivně čeká na požadavky. Klient je iniciátorem relace.

  • Výhody: Centrální správa dat, jednoduché zálohování a kontrola oprávnění.
  • Nevýhody: Server představuje jediný bod selhání (Single Point of Failure) a úzké hrdlo při přetížení.
  • Příklady: Web (HTTP), E-mailové servery, Databáze MySQL, DNS, DHCP.

Model Peer-to-Peer (P2P)

Decentralizovaný model. Každý zapojený uzel (Peer) vystupuje současně jako klient i server. Data si uzly sdílí přímo mezi sebou.

  • Výhody: Vysoká odolnost proti výpadku, škálovatelnost (čím více stahujících, tím vyšší celková kapacita).
  • Nevýhody: Obtížné zabezpečení a dohled, uzly se dynamicky odpojují a připojují.
  • Příklady: BitTorrent, distribuované blockchainy (Bitcoin), sdílení souborů IPFS.
Webové služby

Webová komunikace: Rodina protokolů HTTP a HTTPS

World Wide Web je dominantní službou moderního Internetu. Přenos hypertextových stránek se vyvíjí od jednoduchého textu po extrémně optimalizované binární toky.

Základní HTTP a bezpečné HTTPS

  • HTTP (Port 80 / TCP): Nešifrovaný textový protokol. Všechny požadavky (GET, POST) a odpovědi putují sítí v čitelném tvaru – zranitelné vůči odposlechu (Eavesdropping).
  • HTTPS (Port 443 / TCP): HTTP zapouzdřené do kryptografické vrstvy TLS. Zajišťuje důvěrnost, integritu a ověření identity webu. Dnes naprostý globální standard.

Evoluce: HTTP/1.1 → HTTP/2 → HTTP/3

HTTP/1.1: Textový formát, perzistentní spojení (Keep-Alive), trpí blokováním čela fronty (HOLB) na úrovni aplikačních požadavků.
HTTP/2: Binární protokol, multiplexing stovek požadavků v jediném TCP spojení, komprese hlaviček HPACK.
HTTP/3: Přechod na UDP (protokol QUIC)! Eliminuje HOLB na transportní vrstvě a umožňuje okamžitý 0-RTT start spojení.
Infrastrukturní pilíře

Infrastrukturní služby: DNS a DHCP

Dva neviditelné protokoly, bez kterých by se běžný uživatel do sítě vůbec nepřipojil.

DNS (Domain Name System • Port 53)

Telefonní seznam Internetu. Převádí snadno zapamatovatelná doménová jména (např. sps.cz) na číselné IP adresy (IPv4 / IPv6), které potřebují směrovače.

  • Transport: Běží primárně nad UDP pro rychlost, TCP využívá pro zónové přenosy a velké odpovědi.
  • Hierarchie: Distribuovaný strom kořenových (Root), TLD (.cz) a autoritativních serverů.

DHCP (Dynamic Host Configuration • Port 67/68)

Automatická konfigurace koncových zařízení. Při připojení kabelem či Wi-Fi zajistí automatické přidělení IP adresy, masky, brány i DNS serverů.

  • Transport: Běží nad UDP pomocí broadcastu.
  • Mechanismus: Čtyřkrokový proces DORA (Discover, Offer, Request, Acknowledge).
Elektronická pošta

E-mailový ekosystém: Odesílání (SMTP) a příjem (POP3/IMAP)

E-mail je jedním z nejstarších distribuovaných systémů. Zásadně rozlišuje mezi protokolem pro odesílání mezi servery a protokoly pro přístup uživatele k poštovní schránce.

SMTP (Port 25 / 587)

Odesílání pošty

Simple Mail Transfer Protocol slouží pro přenos zprávy z klienta na server a následné předávání (relay) mezi poštovními servery na celém světě.

POP3 (Port 110 / 995)

Stahování pošty

Post Office Protocol stáhne zprávy ze serveru do lokálního počítače a ze serveru je smaže. Zastaralý model, nevhodný pro více zařízení (mobil + notebook).

IMAP (Port 143 / 993)

Synchronizace na serveru

Internet Message Access Protocol nechává zprávy i složky uložené přímo na serveru. Umožňuje bezchybnou synchronizaci napříč všemi zařízeními.

Správa a soubory

Přenos souborů a vzdálená správa: FTP, SMB, SSH a RDP

Bezpečné i historické standardy pro sdílení dat a dálkovou konfiguraci serverů.

Vzdálená správa (SSH vs. Telnet & RDP)

  • SSH (Port 22 / TCP): Bezpečný šifrovaný přístup k příkazové řádce Linuxu a síťových prvků Cisco. Umožňuje autentizaci heslem nebo asymetrickým klíčem.
  • Telnet (Port 23 / TCP): Zastaralý nešifrovaný textový terminál. Hesla přenáší v čistém textu – dnes zakázán.
  • RDP (Port 3389 / TCP): Vzdálená grafická plocha Windows. Umožňuje práci s GUI vzdáleného počítače.

Sdílení a přenos souborů (FTP, TFTP, SMB)

  • FTP (Port 20/21 / TCP): Tradiční přenos souborů. Využívá dvě spojení – řídicí (21) a datové (20).
  • TFTP (Port 69 / UDP): Extrémně jednoduchý přenos bez přihlášení, využívaný pro bootování počítačů po síti (PXE) a zálohy firmware.
  • SMB (Port 445 / TCP): Sdílení složek, disků a tiskáren v lokální síti Windows (Server Message Block).
Síťový provoz

Dohledové a systémové protokoly: SNMP, Syslog a NTP

Tyto protokoly zajišťují, aby administrátoři měli přesný přehled o stavu, vytížení a událostech v síti.

SNMP (Port 161/162 / UDP)

Simple Network Management Protocol. Dohledové servery periodicky dotazují routery a switche na využití paměti, teplotu a propustnost rozhraní (MIB databáze).

Syslog (Port 514 / UDP)

Centralizovaný sběr systémových zpráv. Síťové prvky odesílají hlášení o chybách, přihlášení uživatelů a pádech linek na centrální logovací server.

NTP (Port 123 / UDP)

Network Time Protocol. Synchronizuje hodiny na zařízeních na zlomky milisekund. Klíčové pro správné časové razítko logů a platnost TLS certifikátů.

Enkapsulace L7 → L4

PDU zpráva a napojení na transportní vrstvu

Aplikační vrstva vytváří čistá data (Message). K jejich odeslání do sítě však musí zvolit vhodný transportní protokol (TCP nebo UDP).

Volba transportu podle požadavků aplikace

  • Aplikace volí TCP, pokud: Nesmí dojít ke ztrátě ani jediného bajtu a data musí dorazit přesně v původním pořadí (HTML stránka, e-mail, bankovní transakce, přenos souboru).
  • Aplikace volí UDP, pokud: Záleží na okamžité rychlosti a minimální latenci, přičemž občasná ztráta paketu je přípustná (hlasový hovor, online hraní, video stream, bleskový DNS dotaz).

Enkapsulace aplikační zprávy

1. Aplikační zpráva (Data / Message):

HTTP GET požadavek, DNS dotaz, soubor k odeslání.

2. Předání transportní vrstvě L4:

Transportní vrstva data rozseká na segmenty a přidá číslo zdrojového a cílového portu (např. Port 443 pro HTTPS).

Rekapitulace SPŠ

Strukturované shrnutí: Aplikační vrstva v kostce

Rychlý přehled pro zkoušení a orientaci v protokolech aplikační vrstvy.

Architektury a principy

  • Spojení vrstev: V modelu TCP/IP slučuje aplikační vrstva funkce vrstev L5, L6 a L7 modelu OSI.
  • Klient-Server: Centralizovaný model (web, databáze), kde server naslouchá na stálém well-known portu.
  • Peer-to-Peer: Distribuovaný model (BitTorrent), kde každý uzel vystupuje jako klient i server současně.

Klíčové protokoly ke zkoušení

  • Web: HTTP (80) nešifrovaný vs. HTTPS (443) šifrovaný přes TLS.
  • Infrastruktura: DNS (53 – překlad jmen) a DHCP (67/68 – automatická IP konfigurace).
  • Pošta: SMTP (25 – odesílání) vs. IMAP (143 – synchronizace) a POP3 (110 – stažení).
  • Správa: SSH (22 – bezpečný terminál) vs. Telnet (23 – nebezpečný textový terminál).
Ověření znalostí

Kontrolní otázky pro upevnění látky

Otestujte své porozumění aplikační vrstvě. Zkuste si nejprve odpovědět sami a poté rozbalte nápovědu.

01. Jaký je rozdíl mezi pojetím aplikační vrstvy v modelu ISO/OSI a v modelu TCP/IP?
Model ISO/OSI rozděluje horní část do tří samostatných vrstev: L5 Relační (řízení relací), L6 Prezentační (kódování, komprese, šifrování) a L7 Aplikační (uživatelské rozhraní). V praktickém modelu TCP/IP jsou všechny tyto tři funkce sloučeny do jediné Aplikační vrstvy a jsou implementovány přímo v rámci konkrétního protokolu.
02. Proč se pro elektronickou poštu používá jiný protokol pro odesílání (SMTP) a jiný pro čtení schránky (IMAP / POP3)?
SMTP je protokol typu „push“ – slouží k doručení zprávy od odesílatele na server a následnému předávání mezi servery po síti. Poštovní server příjemce však nemůže zprávu přímo „vnutit“ do vypnutého mobilu nebo notebooku. Uživatel si proto poštu stahuje / synchronizuje ze své schránky přes protokol typu „pull“ (IMAP nebo POP3), až když aplikaci spustí.
03. V čem spočívá zásadní rozdíl mezi architekturou Klient-Server a architekturou Peer-to-Peer (P2P)?
V modelu Klient-Server existuje centralizovaný server s pevnou IP adresou, který obsluhuje pasivní klienty. Server je jediným centrálním bodem správy (ale i možného výpadku). V síti P2P má každý zapojený uzel (peer) rovnocennou roli – vystupuje současně jako klient i server a data se vyměňují přímo mezi uzly bez nutnosti centrálního serveru.
04. Proč je protokol Telnet v moderních počítačových sítích přísně zakázán a nahrazen protokolem SSH?
Telnet přenáší veškerou komunikaci včetně uživatelských jmen a hesel v nešifrované podobě (čistý text). Kdokoli v síti může pomocí odposlechu (např. v programu Wireshark) hesla okamžitě přečíst. Protokol SSH veškerý provoz šifruje asymetrickou a symetrickou kryptografií a chrání integritu zpráv.
