Cíl projektu: Co dnes postavíme?

Lehká webová aplikace s REST API poskytující informace o stavu systému a kontejneru.

Vlastnosti aplikace

  • Backend v Node.js: Jednoduchý HTTP server bez těžkých závislostí naslouchající na portu 3000.
  • Statické UI: Responzivní HTML/CSS stránka s živými daty o běhu kontejneru (hostname, OS, RAM).
  • 100% Nezávislost: Na svém počítači nemusíte mít nainstalovaný Node.js! Veškerý runtime si stáhne a spustí Docker sám uvnitř kontejneru.

Struktura souborů v projektu

demo-app/
├── server.js         // Logika HTTP serveru
├── package.json      // Metadata projektu
├── .dockerignore     // Vyloučené soubory
├── Dockerfile        // Předpis pro sestavení
└── public/
    └── index.html    // Webová stránka

Krok 1: Příprava Dockeru na Windows, Linuxu a Macu

Jak zprovoznit kontejnerový engine na vaší platformě.

Windows 10/11

1. Otevřete PowerShell jako správce a spusťte:

wsl --install

2. Stáhněte a nainstalujte Docker Desktop (v nastavení zaškrtněte Use the WSL 2 based engine).

Linux (Ubuntu/Debian)

Nativní instalace přímo z balíčkového manažeru:

sudo apt update && sudo apt install -y docker.io
sudo usermod -aG docker $USER

Po odhlášení a přihlášení můžete používat docker bez sudo.

macOS (Apple Silicon / Intel)

Stáhněte Docker Desktop pro Mac (podle čipu M1/M2/M3 nebo Intel) nebo použijte lehkou alternativu:

brew install colima docker
colima start
$docker --version && docker run hello-world # Ověření, že Docker spolehlivě běží

Krok 2: Zdrojový kód aplikace (server.js)

Vytvoříme jednoduchý HTTP server bez externích frameworků.

server.js Node.js Vanilla HTTP 
const http = require('http');
const os = require('os');
const PORT = process.env.PORT || 3000;

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({
    status: 'online',
    message: 'Ahoj ze sveta Docker kontejneru!',
    containerHostname: os.hostname(),
    platform: os.platform(),
    uptimeSeconds: Math.round(process.uptime()),
    timestamp: new Date().toISOString()
  }, null, 2));
});

server.listen(PORT, '0.0.0.0', () => {
  console.log(`Server nasloucha na portu ${PORT}`);
});
package.json Definice projektu 
{
  "name": "docker-demo-app",
  "version": "1.0.0",
  "description": "Ukazkovy kontejner pro SPS",
  "main": "server.js",
  "scripts": {
    "start": "node server.js"
  }
}
Všimněte si: nasloucháme na 0.0.0.0, což umožní přijímat požadavky zvenčí kontejneru (naslouchání na localhost / 127.0.0.1 by uvnitř kontejneru bylo nepřístupné z hostitele!).

Krok 3: Tvorba souboru .dockerignore

Proč je tento soubor často důležitější než samotný Dockerfile?

.dockerignore Vyloučené soubory a složky 
node_modules
npm-debug.log
.git
.gitignore
.env
README.md
.DS_Store

Co se stane bez .dockerignore?

  • Pomalý build: Docker před zahájením stavby posílá celý kontext složky do daemonu. Pokud máte lokální node_modules nebo .git, posíláte zbytečně gigabajty dat.
  • Rozbití binárek: Moduly zkompilované na vašem Windows nebo Macu by se zkopírovaly do Linux kontejneru a aplikace by havarovala.
  • Bezpečnost: Nechtěný únik privátních klíčů ze souboru .env do veřejného obrazu.

Krok 4: Psaní produkčního Dockerfile

Čistý a bezpečný předpis pro vytvoření minimálního obrazu.

Dockerfile Předpis sestavení 
# 1. Bázový obraz: lehký Alpine Linux s Node 20
FROM node:20-alpine

# 2. Vytvoření a nastavení pracovní složky
WORKDIR /usr/src/app

# 3. Zkopírování definice závislostí
COPY package*.json ./

# 4. Zkopírování zbytku aplikace
COPY . .

# 5. Bezpečnost: běh pod ne-root uživatelem
USER node

# 6. Dokumentace portu
EXPOSE 3000

# 7. Startovací příkaz
CMD ["node", "server.js"]

Proč zvolit bázi alpine?

Standardní obraz node:20 (založený na Debianu) má velikost kolem 1 100 MB.

Oproti tomu node:20-alpine zabírá pouhých cca 180 MB! Menší obraz se rychleji stahuje, spotřebovává méně paměti a má menší plochu pro případné bezpečnostní zranitelnosti.

Krok 5: Sestavení obrazu (docker build)

Převod textového předpisu do hotového spustitelného obrazu.

TERMINÁL Příkaz sestavení
$docker build -t sps-demo-app:1.0 .
# Tečka na konci označuje aktuální adresář!
[+] Building 2.4s (8/8) FINISHED
=> [1/4] FROM docker.io/library/node:20-alpine
=> [2/4] WORKDIR /usr/src/app
=> [3/4] COPY package*.json ./
=> [4/4] COPY . .
=> naming to docker.io/library/sps-demo-app:1.0

Rozbor parametrů příkazu:

  • -t sps-demo-app:1.0: Parametr -t (tag) pojmenuje obraz názvem a verzí. Pokud verzi neuvedete, použije se :latest.
  • Tečka . na konci: Určuje tzv. build context – cestu ke složce, kde Docker hledá soubor Dockerfile a odkud kopíruje soubory.
  • Kontrola výsledku: Napište docker images a uvidíte svůj nový obraz v seznamu.

Krok 6: Spuštění a otevření v prohlížeči

Přetvoření obrazu v živý, běžící kontejner.

TERMINÁL Spuštění kontejneru
$docker run -d -p 3000:3000 --name web-sps sps-demo-app:1.0
# Výstup: 64místný hash běžícího kontejneru
$docker ps

Co tyto parametry znamenají?

  • -d (detached mode): Spustí kontejner na pozadí, nezablokuje vám terminál.
  • -p 3000:3000: Propojí port 3000 vašeho počítače s portem 3000 uvnitř kontejneru.
  • --name web-sps: Přidělí kontejneru přátelský lidský název místo náhodného generovaného jména.
Otevřete prohlížeč na adrese: http://localhost:3000 – a uvidíte živý JSON výstup s ID vašeho kontejneru!

Krok 7: Práce s běžícím kontejnerem (Logy a Shell)

Jak nahlédnout dovnitř kontejneru a sledovat jeho činnost.

TERMINÁL Inspekce a interakce
$docker logs -f web-sps # živý stream logů
$docker exec -it web-sps sh # vstup do shellu
/usr/src/app $ ls -la
/usr/src/app $ exit
$docker stop web-sps # zastavení
$docker rm web-sps # odstranění

Kouzelný příkaz: docker exec -it

Přepínače -i (interactive) a -t (pseudo-TTY) vám umožní otevřít interaktivní terminálový shell přímo uvnitř běžícího kontejneru.

Můžete tak prozkoumat vygenerované soubory, otestovat síťové spojení příkazem wget nebo ověřit proměnné prostředí příkazem env.

Krok 8: Více kontejnerů s Docker Compose

Jak propojit webovou aplikaci s databází jediným souborem a příkazem.

docker-compose.yml YAML konfigurace služeb 
version: '3.8'

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
    depends_on:
      - redis

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

Spuštění celého stacku jedním příkazem:

$docker compose up -d
# Vše běží a kontejnery se navzájem vidí!
$docker compose down

Docker Compose automaticky vytvoří společnou virtuální síť. Aplikace web se může k databázi připojit přímo pomocí doménového jména redis:6379 bez řešení IP adres!

Shrnutí tématu & Kontrolní otázky

Ověřte si zvládnutí praktického workflow s Dockerem a kontejnerizací.

Shrnutí workshopu:

Vytvořili jsme odlehčený Dockerfile založený na Alpine Linuxu, ochránili kontext před zbytečnými daty pomocí .dockerignore, sestavili obraz příkazem docker build a spustili kontejner s namapovaným portem -p 3000:3000. Pro vícenásobné služby je standardem docker-compose.yml.

1. Proč je v aplikaci nutné naslouchat na adrese 0.0.0.0 a ne 127.0.0.1?
Adresa 127.0.0.1 (localhost) uvnitř kontejneru je dostupná pouze pro procesy běžící v tomtéž kontejneru. Pro příjem požadavků zvenčí (přesměrovaných přes namapovaný port z hostitelského počítače) musí server naslouchat na všech síťových rozhraních kontejneru, což reprezentuje adresa 0.0.0.0.
2. K čemu slouží tečka na konci příkazu docker build -t moje-app .?
Tečka definuje tzv. sestavovací kontext (Build Context) – označuje aktuální pracovní adresář, ve kterém Docker hledá soubor Dockerfile a ze kterého instrukce COPY přenáší soubory do vytvářeného obrazu.
3. Co se stane, když zapomeneme vytvořit soubor .dockerignore?
Docker zkopíruje do sestavovacího kontextu i složky node_modules, .git a skryté soubory s hesly. To mnohonásobně zpomalí build, zvětší výsledný obraz o stovky megabajtů a může způsobit nefunkčnost nativních knihoven na jiné platformě.
4. Jaká je hlavní výhoda nástroje Docker Compose oproti spouštění docker run?
Umožňuje deklarativně v jednom přehledném YAML souboru nadefinovat celou architekturu (web, databáze, cache, sítě, svazky) a celý systém nastartovat i zastavit jediným příkazem (docker compose up / down) bez nutnosti pamatovat si dlouhé parametry v terminálu.
