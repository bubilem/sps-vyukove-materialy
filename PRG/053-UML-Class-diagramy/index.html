Co je UML a proč modelujeme Class diagramy?

Univerzální dorozumívací jazyk softwarových inženýrů vytvořený mezinárodním konsorciem OMG.

Co znamená zkratka UML?

UML (Unified Modeling Language) je standardizovaný grafický notační jazyk pro specifikaci, vizualizaci, konstrukci a dokumentaci softwarových systémů. Vznikl sjednocením metodik softwarových průkopníků (Grady Booch, James Rumbaugh, Ivar Jacobson – tzv. „Tři Amigos").

Proč nestačí jen psát kód?

  • Blueprint stavby: Stejně jako architekt kreslí výkres domu pro zedníky, programátor navrhuje třídy a vazby před samotným kódováním.
  • Nezávislost na jazyku: Stejný diagram tříd lze implementovat v Pythonu, JavaScriptu, PHP, C# i C++.
  • Týmová komunikace: Diagram na jedné stránce popíše to, co by v kódu zabralo desítky souborů a tisíce řádků.
  • Reverzní inženýrství: Moderní IDE (VS Code, JetBrains) umí z UML vygenerovat kostru kódu a naopak.

Dvě hlavní rodiny UML diagramů

Strukturální (Statické)

Popisují pevnou architekturu systému – co v programu existuje:

  • Class Diagram (Třídy) ← Klíčový
  • Object Diagram (Instance)
  • Package Diagram (Balíčky)
  • Component Diagram
Behaviorální (Dynamické)

Popisují chování v čase a předávání zpráv za běhu:

  • Use Case Diagram (Případy užití)
  • Sequence Diagram (Sekvence zpráv)
  • Activity Diagram (Tok činností)
  • State Machine (Stavový automat)
Zásada SPŠ: Class diagram je páteří objektového návrhu. Z něj vychází databázová schémata, aplikační modely i API rozhraní.

Anatomie třídy v UML: Tři oddíly a možnosti zápisu

Standardizovaný obdélník OMG specifikace a různé úrovně detailu v praxi.

<<entity>> User
Oddíl atributů (Stav)
- id: Integer
+ name: String
# passwordHash: String
+ isActive: Boolean = true
Oddíl metod (Chování & Operace)
+ login(password: String): Boolean
+ changePassword(newPassword: String): void
- validateEmail(email: String): Boolean
1. Název třídy (PascalCase) • 2. Atributy (camelCase) • 3. Metody (camelCase / snake_case)

Přesná syntaxe zápisu řádků

// Zápis atributu (notace):
viditelnost name : DataType [multiplicity] = defaultValue
// Zápis metody (notace):
viditelnost methodName(param1: Type): ReturnType

Možnosti zápisu dle účelu:

  • Konceptuální (zjednodušený): Pouze název třídy, nebo jen klíčové názvy bez typů parametrů. Ideální při prvotním návrhu s týmem.
  • Implementační (detailní): Obsahuje kompletní typové signatury, výchozí hodnoty a viditelnosti – slouží jako přímý vzor pro programátora.
  • Vynechání sekce: Pokud třída nemá atributy (např. utilita) nebo metody, daný oddíl lze v diagramu ponechat prázdný, ale vodorovná čára zůstává.

Modifikátory viditelnosti & Datové typy

Jak chránit data objektu (zapouzdření) a jaké typové systémy UML podporuje.

Značení viditelnosti (Visibility)

Znak Modifikátor Význam a dosah v kódu
+ public Veřejný člen – přístupný odkudkoli z celého programu.
- private Soukromý člen – přístupný pouze uvnitř těla této deklarující třídy.
# protected Chráněný člen – přístupný v této třídě a ve všech jejích odvozených potomcích.
~ package Balíčkový přístup – přístupný pouze v rámci stejného namespace / modulu.
Praxe v OOP: Atributy téměř vždy značíme jako - (private) nebo # (protected). Přístup zvenčí zajišťují veřejné metody + (public) – gettery a settery (např. getEmail(), setEmail()).

Standardní datové typy v UML

UML definuje univerzální primitivní typy, které se v různých jazycích mapují na odpovídající klíčová slova:

Integer → Celé číslo (int)
Real / Float → Desetinné číslo
String → Textový řetězec
Boolean → Pravda / Nepravda
void → Metoda nevrací nic
List<T> / T[*] → Kolekce / pole

Uživatelské (vlastní) typy

Typem atributu může být jakákoli jiná třída! Např. - birthDate: DateTime nebo - owner: Customer. Takto vznikají asociace a vazby mezi objekty.

Statický obsah, Abstraktní třídy a Rozhraní

Jak v UML odlišit prvky patřící třídě, neúplné šablony a čisté kontrakty.

Statický obsah Podtržení textu

Členy patřící celé třídě, nikoli konkrétní instanci (např. matematické konstanty UPPER_SNAKE_CASE, pomocné tovární metody).

Calculator
+ PI: Float = 3.1415
+ power(base: Float, exp: Float): Float
Pravidlo UML: Statický atribut i metoda se zapisují podtrženým písmem nebo tagem {static}.
Abstraktní třída Kurzíva textu

Neúplná třída sloužící jako společný předek. Nelze z ní vytvořit instanci (operátorem new).

<<abstract>> Shape
# color: String
+ calculateArea(): Float
+ render(): void
Pravidlo UML: Název abstraktní třídy a neimplementovaných metod se píše kurzívou nebo se uvede <<abstract>>.
Rozhraní (Interface) <<interface>>

Čistý kontrakt – předpis metod bez atributů a bez implementace, který se třídy zavazují splnit.

<<interface>> IExportable
— žádné atributy stavu —
+ exportToJson(): String
+ exportToXml(): String
Pravidlo UML: Označuje se stereotypem <<interface>>. Všechny metody jsou ze své podstaty veřejné a abstraktní.

Vztahy mezi třídami: Dědičnost & Implementace

Vztahy na úrovni definice typů: klasifikační strom a závazné kontrakty.

1. Generalizace (Dědičnost)

Vztah IS-A

Potomek je specializovaným druhem předka. Dědí všechny jeho atributy a metody a může přidat své vlastní nebo existující přepsat (override).

Plná čára s velkým NEVYPLNĚNÝM trojúhelníkem směřujícím k předkovi
Klíčová slova v kódu: class Dog extends Animal (JS, PHP, Java, C#) nebo class Dog(Animal): (Python).

2. Realizace (Implementace rozhraní)

Vztah CAN-DO

Třída se formálně zavazuje poskytnout těla všem metodám předepsaným v rozhraní (interface). Třída může implementovat i více rozhraní současně.

ČÁRKOVANÁ čára s velkým NEVYPLNĚNÝM trojúhelníkem směřujícím k rozhraní
Klíčová slova v kódu: class Car implements IDrivable (PHP, TS, Java) nebo dědění z ABC abstraktní třídy (Python).
Pozor na častou chybu: Šipka v obou případech vždy ukazuje směrem NA PŘEDKA (nebo na ROZHRANÍ)! Trojúhelník je vždy dutý (nevyplněný).

Vztahy mezi objekty: Kompozice, Agregace, Asociace

Jak spolu instance koexistují v paměti a jaký mají životní cyklus při zániku.

Kompozice

OWNS-A
Pevné složení • Plný kosočtverec ◆

Silná vazba vlastnictví. Součást vzniká uvnitř celku a nemůže bez něj existovat. Zánik celku automaticky zničí i součást.

Car ◆────── Engine
Order ◆──── OrderItem
Engine vzniká uvnitř Car. Sešrotování auta = zničení motoru.

Agregace

HAS-A
Volné složení • Prázdný kosočtverec ◇

Slabá vazba sdružení. Součást je vytvořena samostatně a do celku pouze přiřazena. Při zániku celku součást PŘEŽÍVÁ.

Department ◇──── Teacher
Course ◇──── Student
Zrušení katedry neznamená zánik učitele. Existuje dál!

Asociace & Závislost

KNOWS / USES
Spolupráce • Čára / Šipka • ──> / - ->

Asociace: Strukturální vztah (zná přes atribut).
Závislost: Dočasné použití (objekt jako parametr metody či lokální proměnná).

Order ──> Customer
Order - -> EmailService
Order zná Customer a dočasně zavolá EmailService.
Násobnosti (Kardinalita) na koncích vazeb:
1 – právě jeden 0..1 – nula nebo jeden * / 0..* – libovolně mnoho 1..* – alespoň jeden

Komplexní ukázka: Architektura E-shopu

Všechny prvky v jednom diagramu: Rozhraní, abstraktní třída, dědičnost, statika, agregace i kompozice.

1. Rozhraní & Realizace (Zelená vazba)

IPayable předepisuje platební kontrakt metody pay(). Třída Customer jej realizuje čárkovanou šipkou s trojúhelníkem.

2. Abstraktní třída & Dědičnost (Fialová / Bílá)

User je abstraktní (kurzíva). Má chráněný atribut #email a abstraktní metodu getRole(). Třída Customer z ní dědí plnou čarou s trojúhelníkem.

3. Agregace vs. Kompozice v objednávce

Customer ←◇ Order: Agregace (prázdný kosočtverec). Zákazník existuje samostatně i po smazání objednávky.
Order ◆→ OrderItem: Kompozice (plný kosočtverec). Položky patří výhradně objednávce a zánikem objednávky zaniknou.

4. Statický obsah v Order

Atribut createdCount a metoda generateOrderNumber() jsou podtržené – patří třídě Order, nikoli jednotlivým instancím.

Ověření znalostí (Klikněte pro odpověď)


            

              

                1. Jaký je klíčový rozdíl mezi kompozicí a agregací?
                
              

              

                V životním cyklu součástí: Při kompozici (plný kosočtverec ◆) část nemůže existovat bez celku – pokud celek zanikne, zaniká i součást. U agregace (prázdný kosočtverec ◇) část existuje nezávisle a zánik celku přežije (např. student po zrušení třídy).
              

            


            

              

                2. Jak v UML diagramu poznáme statický atribut nebo metodu?
                
              

              

                Statický atribut i statická metoda jsou zapsány podtrženým textem (např. createdCount: Integer), případně označeny doplňkovým tagem {static}.
              

            


            

              

                3. Čím se v UML liší šipka dědičnosti od šipky rozhraní?
                
              

              

                Obě mají velký prázdný trojúhelník ukazující na cíl, ale dědičnost (generalizace) používá plnou čáru, zatímco realizace rozhraní používá čárkovanou čáru.
              

            


            

              

                4. Co v UML označuje symbol mřížky (#) u atributu?
                
              

              

                Značí modifikátor viditelnosti protected (chráněný). K takovému členu mají přístup metody samotné třídy a všechny její odvozené dceřiné třídy (dědici), ale nikoli vnější okolní kód.
              

            


            

              

                5. Na které straně vztahu se kreslí kosočtverec u kompozice?
                
              

              

                Kosočtverec (plný i prázdný) se vždy umisťuje na stranu CELKU (vlastníka), nikoli na stranu části! Část je na opačném konci spojnice.
