Problém: „Na mém počítači to fungovalo!“

Klasické noční můry nasazování softwaru do produkčního prostředí.

Matice pekel (Dependency Hell)

  • Různé verze runtime: Vývojář má na notebooku Python 3.12 s novou syntaxí; produkční server má starý Python 3.8.
  • Chybějící systémové balíčky: Aplikace potřebuje systémovou knihovnu libpng nebo openssl, která na serveru chybí.
  • Konflikty mezi projekty: Projekt A potřebuje Node 16, zatímco Projekt B na stejném serveru vyžaduje Node 20.

Řešení: Kontejner jako námořní přepravník

Před vynálezem normalizovaných lodních kontejnerů se zboží nakládalo pytel po pytli a každá loď potřebovala jinou manipulaci. Kontejner standardizoval rozměr: jeřábu je jedno, zda je uvnitř káva nebo auta.

Docker v IT: Zabalí kód, runtime, systémové nástroje a konfiguraci do jediného standardizovaného balíčku, který běží 100% stejně na Windows, Macu i linuxovém clusteru.

Virtuální stroj (VM) vs. Kontejner

Proč kontejnery nahradily těžkopádnou plnou virtualizaci.

Virtuální stroj (VMware / VirtualBox)

Aplikace A & B
Knihovny a binárky
Celý Guest OS (desítky GB!)
Hypervisor (Type 1 / 2)
Hostitelský OS + Fyzický HW

Těžkopádné: start trvá minuty, emuluje virtuální hardware, spotřebovává gigabajty RAM na vlastní operační systém.

Docker Kontejner

Aplikace A & B (Procesy)
Knihovny a binárky
Docker Daemon / Engine
Sdílené jádro (Linux Kernel)
Fyzický hardware

Bleskové: start v milisekundách, sdílí přímo jádro hostitele (namespaces & cgroups), nulová režie na duplicitní OS.

Klíčový pojmový aparát Dockeru

Čtyři základní entity, které musíte rozlišovat.

Docker Image (Obraz)

Neměnná šablona (blueprint) pro vytvoření kontejneru. Obsahuje souborový systém se všemi nainstalovanými balíčky, kódem a metadaty. Jako třída v OOP.

Docker Container (Kontejner)

Běžící, živá instance vytvořená z obrazu. Má vlastní procesový prostor, síťové rozhraní a tenkou zapisovatelnou vrstvu. Jako objekt v OOP.

Docker Engine / Daemon

Služba běžící na pozadí operačního systému, která se stará o sestavování obrazů, spouštění kontejnerů a správu sítí a disků.

Docker Hub (Registr)

Veřejný cloudový katalog (obdoba GitHubu pro obrazy), odkud si můžete stáhnout hotové oficiální obrazy: python, node, nginx, postgres.

Dockerfile pod mikroskopem: Kuchařka pro Image

Jednoduchý textový soubor bez přípony, který krok za krokem definuje sestavení obrazu.

FROM node:20-alpine Bázový obraz. Stavíme na oficiálním odlehčeném Linuxu s Node.js 20.
WORKDIR /app Nastaví pracovní adresář uvnitř kontejneru pro všechny další příkazy.
COPY package*.json ./ Zkopíruje soubory definující závislosti z vašeho počítače do kontejneru.
RUN npm install Spustí příkaz v průběhu sestavení (nainstaluje knihovny).
COPY . . Zkopíruje zbytek zdrojového kódu aplikace do obrazu.
EXPOSE 3000 Informativní dokumentace portu, na kterém aplikace uvnitř naslouchá.
CMD ["node", "server.js"] Výchozí příkaz, který se spustí, když kontejner nastartuje (ne při sestavování!).

Vrstvová architektura souborů a Cache

Proč se druhý build vašeho Docker obrazu dokončí za 1 sekundu.

Vrstvový souborový systém (UnionFS)

Každý řádek v Dockerfile (FROM, COPY, RUN) vytvoří novou samostatnou pouze pro čtení (read-only) vrstvu.

Pokud se změní pouze jeden řádek kódu v server.js, Docker znovu sestaví pouze poslední vrstvu. Všechny předchozí vrstvy (např. stažení Linuxu a instalace balíčků) vezme z cache!

Doporučený trik: Oddělení závislostí

Vždy nejprve kopírujte definici balíčků (package.json nebo requirements.txt) a spusťte instalaci, a až potom zkopírujte zdrojový kód aplikace.

Díky tomu se obrovské balíčky nebudou stahovat znovu při každé drobné úpravě HTML nebo JS souboru!

Základní příkazy v Docker CLI

Přehled nejpoužívanějších příkazů pro každodenní správu.

Práce s obrazy (Images)

  • docker build -t moje-app . – sestaví obraz z aktuálního Dockerfile a pojmenuje jej.
  • docker images – vypíše všechny stažené a sestavené obrazy na vašem disku.
  • docker rmi <id> – smaže nepoužívaný obraz.
  • docker pull nginx – stáhne hotový obraz z Docker Hubu.

Práce s kontejnery (Containers)

  • docker run -d -p 8080:80 nginx – spustí kontejner na pozadí a namapuje port.
  • docker ps – seznam aktuálně běžících kontejnerů.
  • docker stop <id> – zastaví běžící kontejner.
  • docker logs <id> – zobrazí výstup konzole zevnitř kontejneru.

Porty a perzistence dat (Docker Volumes)

Jak komunikovat s kontejnerem zvenčí a nepřijít o data v databázi.

Mapování portů: -p 8080:80

Kontejner má vlastní virtuální síťovou kartu. Aby byl dostupný ve vašem prohlížeči, musíte propojit port hostitele s portem kontejneru:

-p <PORT_HOSTITELE>:<PORT_KONTEJNERU>
Např. -p 8080:80 → prohlížeč: http://localhost:8080

Perzistence a svazky: -v

Kontejnery jsou efemérní (bezstavové) – jakmile kontejner smažete, všechna nově vytvořená data uvnitř zaniknou!

-v moje-data:/var/lib/postgresql/data
Trvalá data databáze se ukládají na disk hostitele mimo kontejner.

Prostředí: Docker Desktop vs. Linux Server

Jak se liší vývojářské prostředí od ostrého produkčního nasazení.

Docker Desktop (Windows & macOS)

  • Grafická aplikace s přehledem kontejnerů, logů a využití RAM/CPU.
  • Jelikož Windows ani macOS nemají Linux kernel, Docker Desktop spouští odlehčenou linuxovou virtualizaci (WSL2 na Windows, Virtualization framework na Macu).
  • Určeno pro lokální vývoj a ladění.

Headless Docker Engine (Linux servery)

  • Běží nativně přímo na linuxovém jádře bez jakékoli virtualizační vrstvy.
  • Žádné grafické rozhraní; ovládá se přes terminál nebo orchestrátory (Docker Swarm, Kubernetes).
  • Maximální výkon, minimální spotřeba paměti a provoz 24/7.

Shrnutí tématu & Kontrolní otázky

Ověřte si porozumění základům kontejnerizace v Dockeru.

Shrnutí klíčových bodů:

Docker kontejner sdílí jádro hostitelského OS, díky čemuž startuje bleskově a spotřebovává zlomek prostředků oproti virtuálnímu stroji. Docker Image vzniká ze souboru Dockerfile, využívá cachování vrstev a při spuštění se konfigurují porty a trvalé svazky (Volumes).

1. Jaký je hlavní architektonický rozdíl mezi kontejnerem a virtuálním strojem?
Virtuální stroj obsahuje kompletní vlastní operační systém (Guest OS) a běží nad hypervisorem emulujícím hardware. Kontejner sdílí jádro (kernel) hostitelského operačního systému a izoluje pouze procesy a knihovny aplikace, což šetří gigabajty paměti a procesorový čas.
2. K čemu slouží instrukce WORKDIR v souboru Dockerfile?
Nastavuje výchozí pracovní adresář uvnitř kontejneru pro všechny následující instrukce (COPY, RUN, CMD). Pokud složka neexistuje, automaticky ji vytvoří.
3. Co přesně znamená parametr -p 8080:80 při spuštění příkazu docker run?
Mapuje síťový port 8080 na vašem fyzickém počítači (hostiteli) na vnitřní port 80 uvnitř izolovaného kontejneru. Do aplikace v kontejneru se pak dostanete přes webový prohlížeč na adrese http://localhost:8080.
4. Proč jsou pro databáze v Dockeru nezbytné Docker Volumes?
Kontejnery jsou ze své podstaty efemérní (bezstavové) a jakákoli data zapsaná přímo do kontejneru se při jeho smazání nevratně ztratí. Docker Volume přesměruje ukládání dat na trvalé úložiště hostitelského počítače, takže data přežijí i restart nebo aktualizaci kontejneru.
