Interaktivní Krokovací simulátor na grafu

Co je cesta v grafu a jaké úlohy řešíme?

V grafových strukturách rozlišujeme mezi pouhou existencí spojení, minimálním počtem přestupů a nejlevnější váženou trasou.

Matematická a datová definice cesty

Cesta (Path) v grafu G = (V, E) je konečná posloupnost vrcholů (v0, v1, v2, …, vk), ve které mezi každými dvěma sousedními vrcholy existuje platná hrana:

(vi, vi+1) ∈ E  •  pro všechna i ∈ {0, 1, …, k − 1} Kde v0 je počáteční uzel (Start) a vk je koncový cíl (Target).
  • Prostá cesta (Simple Path): Cesta, ve které se žádný uzel neopakuje (neobsahuje vnitřní cykly).
  • Délka v neváženém grafu: Počet hran na cestě (k).
  • Cena ve váženém grafu: Součet vah všech hran ∑ w(vi, vi+1).
Základní programátorská zásada: Než začneme optimalizovat délku či cenu trasy, musíme nejprve umět spolehlivě odpovědět, zda trasa mezi uzly vůbec existuje.

3 základní otázky v praxi vývojáře

  1. Dosažitelnost (Reachability): Existuje vůbec cesta z A do E? → Vrací boolean True / False.
  2. Nejkratší nevážená cesta: Která trasa má nejméně mezikroků/přestupů? → Řeší algoritmus BFS.
  3. Nejkratší vážená cesta: Která trasa má nejmenší čas, latenci či cenu? → Řeší Dijkstra a Bellman-Ford.

Test existence cesty (Dosažitelnost v grafu)

Základní a nejrychlejší rozhodovací algoritmus: Je uzel B dosažitelný z uzlu A?

Problém cyklu a role množiny visited

V obecném grafu mohou hrany tvořit kružnice (cykly). Kdybychom sousedy procházeli naivně bez paměti, program by navštívil A → B → C → A → B … a uvízl v nekonečné smyčce.

Pravidlo spolehlivého průchodu: Každý navštívený vrchol musíme okamžitě zaregistrovat do množiny visited = set() s přístupem v čase O(1)!

Princip testu existence:

  • Vložíme startovní uzel do zásobníku nebo fronty.
  • Dokud zásobník není prázdný, vyjmeme uzel. Pokud je to hledaný cíl, ihned vrátíme True.
  • Pokud cíl není, označíme uzel jako navštívený a na zásobník přidáme všechny jeho dosud nenavštívené sousedy.
  • Vyprázdní-li se zásobník bez nalezení cíle, vrátíme False.
Python 3 def has_path(graph, start, target): """ Vrátí True, pokud existuje jakákoli cesta ze start do target. Jinak vrátí False. """ if start == target: return True # Množina již navštívených uzlů (zamezí zacyklení) visited = set() # Zásobník pro uzly čekající na prozkoumání stack = [start] while stack: current = stack.pop() if current == target: return True if current not in visited: visited.add(current) # Přidáme všechny sousedy, kteří ještě nebyli navštíveni for neighbor in graph.get(current, []): if neighbor not in visited: stack.append(neighbor) # Prošli jsme všechny dostupné uzly a cíl jsme nenašli return False
Složitost testu existence: Časová složitost je O(|V| + |E|), paměťová složitost je O(|V|) pro evidenci navštívených vrcholů.

Prohledávání do hloubky (DFS – Depth-First Search)

Strategie: Jdi co nejhlouběji podél jedné větve. U slepé uličky se vrať na poslední křižovatku (Backtracking).

Princip LIFO & Metafora bludiště

Algoritmus DFS funguje podobně jako průzkumník v neznámém labyrintu: vybere si jednu odbočku a kráčí stále kupředu, dokud nenarazí na konec. Jakmile narazí na slepou větev, couvne o krok zpět (Backtracking) a zkusí další možnou odbočku.

  • Datová struktura: Zásobník (Stack / LIFO) – poslední přidaný uzel je zkoumán jako první.
  • Implementace: Buď rekurzivně (využívá se systémový zásobník volání funkcí Call Stack), nebo iterativně s vlastním polem stack = [].
  • Klíčová vlastnost: DFS najde cestu rychle a paměťově úsporně, ALE NEGARANTUJE NEJKRATŠÍ CESTU! Může projít zbytečnou velkou oklikou.
Kdy použít DFS: Detekce cyklů v grafu, topologické uspořádání úloh, řešení hlavolamů a bludišť, prohledávání stavového prostoru šachových partií.
Python 3 (DFS Cesta) def dfs_path(graph, start, target, visited=None): """ Nalezne libovolnou platnou cestu z uzlu start do target. Vrací seznam vrcholů na cestě, nebo None pokud cesta neexistuje. """ if visited is None: visited = set() visited.add(start) # Cíl dosažen -> cesta je tvořena tímto uzlem if start == target: return [start] # Rekurzivní zanoření do jednotlivých sousedů for neighbor in graph.get(start, []): if neighbor not in visited: sub_path = dfs_path(graph, neighbor, target, visited) if sub_path is not None: # Sestavíme cestu přidáním počátku na začátek return [start] + sub_path # Z tohoto uzlu žádná cesta do cíle nevede return None

Prohledávání do šířky (BFS – Breadth-First Search)

Strategie: Prozkoumej všechny sousedy ve vzdálenosti 1, pak ve vzdálenosti 2, pak 3... Šíří se jako vlna na rybníku.

Princip FIFO & Zlaté pravidlo BFS

BFS postupuje po soustředných vrstvách. Nejprve navštíví všechny přímé sousedy startu (vrstva 1), teprve poté jejich sousedy (vrstva 2) atd.

Zlaté pravidlo BFS: V neváženém grafu BFS VŽDY garantuje nalezení NEJKRATŠÍ CESTY (s minimálním počtem hran)!
  • Datová struktura: Fronta (Queue / FIFO) – první vložený uzel je první zpracován. V Pythonu používáme collections.deque pro efektivní operaci popleft() v čase O(1).
  • Rekonstrukce cesty: Ukládáme si slovník předchůdců parent[soused] = uzel. Po dosažení cíle zrekonstruujeme trasu zpětným dohledáním.
Kdy použít BFS: Vyhledání nejmenšího počtu přestupů v MHD, doporučení přátel 2. a 3. stupně (sociální sítě), web crawling, výpočet dosahu v tahových hrách.
Python 3 (BFS Nejkratší cesta) from collections import deque def bfs_shortest_path(graph, start, target): """ Nalezne nejkratší cestu v neváženém grafu (min. hran). """ if start == target: return [start] # Fronta uchovává dvojice: (aktuální_uzel, dosavadní_cesta) queue = deque([ (start, [start]) ]) visited = set([start]) while queue: current, path = queue.popleft() # FIFO: bereme z čela fronty for neighbor in graph.get(current, []): if neighbor == target: # První nalezení cíle je zaručeně nejkratší cesta! return path + [neighbor] if neighbor not in visited: visited.add(neighbor) queue.append((neighbor, path + [neighbor])) return None # Cíl není dosažitelný

Srovnání v praxi: Hloubka (DFS) vs. Šířka (BFS)

Dva základní pilíře grafového prohledávání. Jak vybrat správný algoritmus pro konkrétní úlohu?

DFS • Hloubka Zásobník (LIFO)
  • Postup: Noří se do maximální hloubky jedné větve, pak se vrací (Backtracking).
  • Záruka nejkratší cesty: NE – může najít zbytečně dlouhou okliku.
  • Paměťová náročnost: O(hloubka) ≤ O(|V|) – obvykle velmi šetrné k RAM.
  • Typické využití:
    • Hledání cyklů v grafech
    • Topologické třídění závislostí (Make, npm)
    • Generování a řešení bludišť
BFS • Šířka Fronta (FIFO)
  • Postup: Prohledává graf po vlnách/vrstvách vzdálenosti od startu.
  • Záruka nejkratší cesty: ANO (v neváženém grafu s min. počtem hran).
  • Paměťová náročnost: O(šířka) ≤ O(|V|) – může v paměti držet mnoho uzlů naráz.
  • Typické využití:
    • Nejkratší cesta s minimem přestupů
    • Stupně spojení v sociálních sítích
    • Flood Fill (výplň barvou v grafických editorech)

Časová a paměťová složitost při reprezentaci seznamem sousedů

Pro oba algoritmy (BFS i DFS) je při reprezentaci pomocí seznamu sousedů (Adjacency List) časová složitost lineární: O(|V| + |E|), kde |V| je počet uzlů a |E| je počet hran. Každý uzel navštívíme nejvýše jednou a každou hranu prozkoumáme nejvýše jednou.

Vážené grafy a Dijkstrův algoritmus

V reálném světě nemají silnice stejnou délku a optická vlákna stejnou latenci. Hledáme trasu s minimálním součtem vah.

Edsger W. Dijkstra (1956) & Greedy přístup

Proč ve váženém grafu selže BFS? Jediná dálniční hrana může mít délku 120 km, zatímco cesta přes dvě okresní silnice má 30 + 40 = 70 km. BFS by chybně vybralo dálnici, protože má méně hran.

Princip Dijkstrova algoritmu:

  1. Nastav vzdálenost startu dist[start] = 0, všech ostatních uzlů dist[v] = ∞.
  2. Vybírej vždy uzel u s nejmenší dosud známou vzdáleností (pomocí prioritní fronty / Min-Heap).
  3. Pro všechny sousedy v uzlu u otestuj relaxaci hrany.
Kritická podmínka Dijkstrova algoritmu: Všechny váhy hran MUSÍ BÝT NEZÁPORNÉ (w ≥ 0). Pokud by graf obsahoval záporné hrany, hladový předpoklad selže!

Klíčový koncept: Relaxace hrany

Srdcem výpočtu je otázka: „Je levnější jít do uzlu v přímo, nebo vzít zkratku přes uzel u?‟

Pokud dist[u] + w(u, v) < dist[v]: dist[v] = dist[u] + w(u, v)  •  parent[v] = u

Pokud je nová cesta kratší než dosavadní hodnota dist[v], přepíšeme ji novým minimem a aktualizujeme předchůdce.

Efektivita s Min-Heap (Prioritní fronta): Využitím binární haldy (v Pythonu modul heapq) dosáhneme špičkové časové složitosti O((|V| + |E|) · log |V|).

Implementace Dijkstrova algoritmu v Pythonu

Využití standardního modulu heapq (binární halda) pro rychlé vyhledávání minima v čase O(log V).

Python 3 (heapq) import heapq def dijkstra(graph, start, target): """ graph: slovník { uzel: [(soused, vaha), ...] } Vrací: (celkova_cena, nejkratsi_cesta) """ # 1. Pole vzdáleností: start má 0, ostatní nekonečno distances = {node: float('inf') for node in graph} distances[start] = 0 previous = {node: None for node in graph} # 2. Prioritní fronta (Min-Heap): ukládá n-tice (vzdalenost, uzel) pq = [(0, start)] while pq: curr_dist, u = heapq.heappop(pq) # Pokud jsme v haldě našli zastaralý záznam s vyšší cenou, přeskočíme if curr_dist > distances[u]: continue if u == target: break # 3. Relaxace všech odchozích hran for v, weight in graph.get(u, []): new_dist = curr_dist + weight if new_dist < distances[v]: distances[v] = new_dist previous[v] = u heapq.heappush(pq, (new_dist, v)) # 4. Rekonstrukce nalezené trasy od cíle ke startu path = [] curr = target while curr is not None: path.append(curr) curr = previous[curr] path.reverse() return distances[target], path

Rozbor klíčových řádků

  • heapq.heappush(pq, (dist, v)): Ukládáme vzdálenost na první pozici n-tice, protože Python halda řadí prvky podle prvního členu.
  • curr_dist > distances[u]: Rychlé přeskočení "mrtvých" záznamů v haldě. Vznikají, když uzel zlevníme podruhé.
  • Zpětná rekonstrukce: Pole previous umožňuje snadné dohledání trasy pozpátku v čase O(|V|).
Příklad výstupu: Pro graf se startem 'A' a cílem 'F' funkce vrátí např. (8, ['A', 'C', 'B', 'E', 'D', 'F']).

Záporné váhy a Bellman-Fordův algoritmus

Co když hrana představuje slevu či zisk energie se zápornou hodnotou? Zde Dijkstra selhává a nastupuje Bellman-Ford.

Proč Dijkstra selže u záporných vah?

Dijkstra je hladový (Greedy) algoritmus. Jakmile uzel vyjme z prioritní fronty a označí za navštívený, považuje jeho vzdálenost za konečnou a již se k němu nikdy nevrátí.

Pokud by se však za ním nacházela hrana se zápornou vahou (např. −10), celková trasa by mohla zlevnit, ale Dijkstra už to nezjistí!

Princip |V| − 1 kol relaxace

Bellman-Ford nepoužívá hladový výběr. Místo toho provede:

Přesně (|V| − 1) kol relaxace VŠECH hran Nejdelší prostá cesta bez cyklu v grafu o |V| uzlech má nejvýše |V| − 1 hran.

Detekce záporného cyklu: Pokud po (|V| − 1) kolech provedeme ještě jedno kolo navíc a libovolná hrana stále dokáže zlevnit, graf obsahuje záporný cyklus (cesta by mohla zlevňovat donekonečna do −∞).

Python 3 (Bellman-Ford) def bellman_ford(nodes, edges, start): """ edges: seznam n-tic [(odkud, kam, vaha), ...] Vrací slovník nejkratších vzdáleností, nebo vyvolá výjimku při cyklu. """ dist = {node: float('inf') for node in nodes} dist[start] = 0 # 1. Provedeme (|V| - 1) kol relaxace for _ in range(len(nodes) - 1): updated = False for u, v, weight in edges: if dist[u] != float('inf') and dist[u] + weight < dist[v]: dist[v] = dist[u] + weight updated = True if not updated: break # Předčasné ukončení při konvergenci # 2. Kontrola záporného cyklu (|V|-té kolo) for u, v, weight in edges: if dist[u] != float('inf') and dist[u] + weight < dist[v]: raise ValueError("Graf obsahuje záporný cyklus!") return dist
Časová složitost: O(|V| · |E|). Je pomalejší než Dijkstra, ale bezpečný pro finanční a arbitrážní modely se zápornými vahami.

Velký rozcestník: Který algoritmus zvolit?

DFS (Hloubka) Libovolný Nevážený Nerelevantní Zásobník (LIFO) O(|V| + |E|) Ne (libovolná cesta)

Rozhodovací strom programátora (Quick Guide)

Krok 1
Hledáš pouze informaci True/False, zda spojení existuje? → Použij jednoduchý Test existence / DFS s množinou visited.
Krok 2
Je graf nevážený (každý krok stojí stejně) a chceš nejméně kroků? → Použij BFS s frontou FIFO.
Krok 3
Je graf vážený a všechny váhy jsou kladné (w ≥ 0)? → Použij Dijkstrův algoritmus s Min-Heap.
Krok 4
Mohou se v síti vyskytovat záporné váhy hran? → Použij Bellman-Fordův algoritmus pro detekci cyklu a korektní relaxaci.

Shrnutí tématu & Prověření znalostí

Zopakujte si klíčové koncepty a otestujte své znalosti grafových algoritmů před praktickým programováním.

1. Klíčové poznatky

Množina visited je nezbytná prevence zacyklení v cyklických grafech. Všechny základní průchody mají složitost O(|V| + |E|).

2. LIFO vs. FIFO

BFS s frontou vždy najde nejkratší cestu v neváženém grafu. DFS se zásobníkem jde do hloubky a hodí se pro detekci cyklů.

3. Vážené sítě

Dijkstra s Min-Heap nabízí nejlepší rychlost O((|V| + |E|) · log |V|) pro kladné váhy. Bellman-Ford bezpečně odhalí záporné cykly.

Otázka 1 • BFS Garance
Proč BFS v neváženém grafu vždy zaručuje nejkratší cestu, zatímco DFS nikoliv?
BFS prozkoumává uzly systematicky po vrstvách (vzdálenost 1, pak 2, pak 3...). První nalezení cíle proto zaručeně proběhne přes minimální možný počet hran. DFS se naproti tomu noří do hloubky a může dorazit do cíle velkou oklikou.
Otázka 2 • Dijkstrův limit
Z jakého důvodu selže Dijkstrův algoritmus, pokud graf obsahuje hranu se zápornou váhou?
Dijkstra je hladový algoritmus (Greedy). Jakmile uzel vyjme z prioritní fronty a uzavře jej, předpokládá, že žádná další cesta již nemůže celkovou vzdálenost zmenšit. Záporná hrana by však mohla trasu dodatečně zlevnit, což již Dijkstra nedokáže zohlednit.
Otázka 3 • Cykly a paměť
Co se stane, pokud v testu existence cesty zapomeneme evidovat množinu navštívených uzlů (visited)?
V cyklickém grafu (kde existuje kružnice) začne algoritmus donekonečna přeskakovat mezi cyklickými uzly (A → B → C → A...). Dojde k nekonečné smyčce, zaplnění paměti (OutOfMemory) nebo pádu na RecursionError při rekurzi.
Otázka 4 • Bellman-Ford cykly
Proč Bellman-Ford potřebuje právě (|V| − 1) kol relaxace a co znamená změna v |V|-tém kole?
Nejdelší možná prostá cesta bez opakování uzlů v grafu o |V| vrcholech může mít maximálně |V| − 1 hran. Každé kolo garantuje propagaci nejkratší vzdálenosti o další hranu. Pokud i v |V|-tém kole lze vzdálenost snížit, znamená to přítomnost záporného cyklu.
