Evoluce programování: Cesta k objektům

Jak vývojáři řešili rostoucí složitost programů od strojového kódu až po rozsáhlé podnikové architektury.

1950s – 1960s

Nestrukturovaný kód

Příkazy GOTO a lineární skoky v paměti. Kód se při překročení stovek řádků měnil v nepřehledný špagetový kód, kde jakákoli změna rozbila zbytek programu.

1970s

Strukturované & Procedurální

Funkce, procedury a bloky kódu (C, Pascal). Program se dělí na podprogramy, ale data a funkce existují odděleně. Globální proměnné jsou zranitelné vůči nechtěnému přepisu.

1980s – 1990s

Nástup OOP paradigmatu

Jazyky Simula 67, Smalltalk, C++ a následně Java. Zabalení dat a souvisejících operací do jednoho samostatného celku – objektu.

2000s – Dnes

Multiparadigmatický svět

Moderní jazyky (Python, JavaScript/TypeScript, PHP 8+, C#, Rust) kombinují OOP s funkcionálním programováním a asynchronním zpracováním událostí.

Krize softwaru (Software Crisis)

S rostoucím výkonem počítačů začaly vznikat aplikace s miliony řádků kódu (letectví, bankovnictví, operační systémy). Procedurální styl selhával v udržovatelnosti a znovupoužitelnosti. OOP přineslo přirozený model reálného světa: systém se skládá ze spolupracujících entit posílajících si zprávy.

Procedurální vs. Objektový svět v kódu

Porovnání na reálném problému: Správa bankovního účtu a ochrana zůstatku před nepovolenou manipulací.

Procedurální přístup: Data ≠ Funkce

Oddělený stav

Data leží ve volném slovníku nebo poli. Jakákoli funkce či řádek v kódu může přímo změnit zůstatek bez kontroly a validace pravidel.

Procedurální
# Data jsou volný slovník ucet = {"majitel": "Jan", "zustatek": 1000} def vyber_penize(u, castka): if u["zustatek"] >= castka: u["zustatek"] -= castka # Riziko: Kdokoli může data kdykoli pokazit! ucet["zustatek"] = -999999 # Žádná ochrana!
// Data jsou obyčejný objekt bez ochrany let ucet = { majitel: "Jan", zustatek: 1000 }; function vyberPenize(u, castka) { if (u.zustatek >= castka) { u.zustatek -= castka; } } // Riziko: Přímý a nekontrolovaný přepis ucet.zustatek = -999999; // Žádná validace!
// Data leží v asociativním poli $ucet = ["majitel" => "Jan", "zustatek" => 1000]; function vyberPenize(&$u, $castka) { if ($u["zustatek"] >= $castka) { $u["zustatek"] -= $castka; } } // Nebezpečí: Přímé poškození stavu aplikace $ucet["zustatek"] = -999999;

Objektový přístup: Zapouzdřený stav

Stav + Chování

Objekt si chrání svůj vnitřní stav. Změna zůstatku probíhá výhradně přes veřejné rozhraní (metody), které garantuje obchodní pravidla.

Objektové OOP
class BankAccount: def __init__(self, majitel, zustatek): self.majitel = majitel self._zustatek = zustatek # Chráněný atribut def vyber(self, castka): if 0 < castka <= self._zustatek: self._zustatek -= castka return True return False
class BankAccount { #zustatek; // Skutečně privátní pole (od ES2022) constructor(majitel, zustatek) { this.majitel = majitel; this.#zustatek = zustatek; } vyber(castka) { if (castka > 0 && castka <= this.#zustatek) { this.#zustatek -= castka; return true; } return false; } }
class BankAccount { public string $majitel; private float $zustatek; // Privátní atribut public function __construct($majitel, $zustatek) { $this->majitel = $majitel; $this->zustatek = $zustatek; } public function vyber($castka): bool { if ($castka > 0 && $castka <= $this->zustatek) { $this->zustatek -= $castka; return true; } return false; } }

Mentální model: Třída (Předpis) vs. Objekt (Instance)

Základní koncept OOP: Třída existuje pouze jednou jako vzor, instancí může vzniknout nekonečně mnoho.

Třída (Class) • Typ a Předpis

Třída je šablona, architektonický plán nebo razítko. Definuje, jaká data budou budoucí objekty uchovávat (atributy) a jaké akce s nimi bude možné provádět (metody). Třída sama o sobě nemá konkrétní osobní údaje.

Objekt / Instance (Object) • Reálné Bytí

Objekt je konkrétní postavený dům, otisk razítka na papíře nebo upečený dort. Vzniká procesem zvaným instanciace (obvykle klíčovým slovem new nebo voláním třídy). Žije v operační paměti a má svůj vlastní unikátní stav.

Zlaté pravidlo: Z jedné třídy User vytvoříte instance user1 (Petr) i user2 (Eva). Každý má své jméno i heslo, ale oba sdílejí stejné metody prihlasSe() a zmenHeslo().
Instance žijí na haldě (Heap) a každá má vlastní paměťovou adresu i hodnoty atributů.

4 základní pilíře objektově orientovaného programování

Základní stavební kameny, na kterých stojí spolehlivý, rozšiřitelný a bezpečný software.

1. Abstrakce

Výběr pouze podstatných vlastností pro daný kontext a zanedbání nepodstatných detailů.

Příklad: U studenta v IS řešíme ročník a známky, ne barvu jeho bot či oblíbený film.

2. Zapouzdření

Skrytí vnitřního stavu objektu (Private) a poskytnutí bezpečného veřejného rozhraní (Public API).

Příklad: Rychlost auta zvyšujeme plynovým pedálem, nemanipulujeme rukou přímo se vstřikovací tryskou.

3. Dědičnost

Vytvoření nové třídy na základě již existující. Potomek přebírá vlastnosti předka a přidává své specifické.

Příklad: Elektromobil dědí z Auto, ale navíc přidává atribut kapacitaBaterie.

4. Polymorfismus

Mnohotvárnost: stejné volání metody vyvolá různé specifické chování podle typu konkrétního objektu.

Příklad: Voláme zvire.vydejZvuk() – Pes zaštěká, Kočka zamňouká, Kráva zabučí.
Všechny 4 pilíře spolupracují: Abstrakce navrhne model • Zapouzdření ochrání data • Dědičnost ušetří kód • Polymorfismus umožní čisté rozšíření systému.

Pilíře 1 & 2: Abstrakce & Zapouzdření v akci

Jak navrhnout čisté veřejné rozhraní a ochránit vnitřní stav před chybami uživatele či okolního kódu.

Abstrakce: Oddělení CO od JAK

Uživatel třídy Termostat volá metodu nastavTeplotu(22). Nemusí vědět, jaké relé sepne nebo jaký PWM signál mikrokontrolér vygeneruje. Zná pouze veřejný kontrakt.

Zapouzdření (Encapsulation): Black Box

Data jsou uzamčena uvnitř objektu. Zápis je možný pouze přes metody, které ověří podmínky (např. teplota musí být mezi 5 °C a 35 °C). Tím je zaručeno, že objekt nikdy neskončí v neplatném nebo poškozeném stavu.

+ Public API
- Private State
Zapouzdření
class Termostat: def __init__(self, vychozi_teplota=20.0): self.__teplota = vychozi_teplota # Privátní def nastav_teplotu(self, nova_teplota): if 5.0 <= nova_teplota <= 35.0: self.__teplota = nova_teplota return True print("Chyba: Teplota mimo bezpečný rozsah!") return False def ziskej_teplotu(self): return self.__teplota t = Termostat() t.nastav_teplotu(22.5) # OK t.nastav_teplotu(120.0) # Odmítnuto validací!
class Termostat { #teplota; // Privátní proměnná constructor(vychozi = 20.0) { this.#teplota = vychozi; } nastavTeplotu(nova) { if (nova >= 5.0 && nova <= 35.0) { this.#teplota = nova; return true; } console.warn("Chyba: Neplatná teplota!"); return false; } ziskejTeplotu() { return this.#teplota; } } const t = new Termostat(); t.nastavTeplotu(22.5);
class Termostat { private float $teplota; // Skrytý stav public function __construct(float $vychozi = 20.0) { $this->teplota = $vychozi; } public function nastavTeplotu(float $nova): bool { if ($nova >= 5.0 && $nova <= 35.0) { $this->teplota = $nova; return true; } return false; } public function ziskejTeplotu(): float { return $this->teplota; } }

Pilíře 3 & 4: Dědičnost & Polymorfismus

Znovupoužití kódu a jednotné rozhraní pro různorodé objekty bez zbytečných if-else větví.

Dědičnost (Inheritance): Vztah IS-A

Třída Pes je specializací třídy Zvire. Nemusíme znovu psát atributy jmeno a vek – potomek je zdědí od rodiče a pouze doplní specifické chování (štěkání).

Polymorfismus (Mnoho forem)

Máme pole různých zvířat [pes, kocka, krava]. Projdeme je jediným cyklem a zavoláme zvire.vydej_zvuk(). Každý objekt zareaguje po svém, aniž bychom museli zjišťovat jeho typ podmínkami if-else!

Výhoda pro architekturu

Když do hry za měsíc přidáte novou třídu Kacena, existující kód pro vykreslení či ozvučení zvířat nemusíte vůbec měnit.

Polymorfismus
class Zvire: def __init__(self, jmeno): self.jmeno = jmeno def vydej_zvuk(self): pass class Pes(Zvire): def vydej_zvuk(self): return f"{self.jmeno} štěká: Haf haf!" class Kocka(Zvire): def vydej_zvuk(self): return f"{self.jmeno} mňouká: Mňau!" # Polymorfní zpracování seznamu zvirata = [Pes("Alík"), Kocka("Micka")] for z in zvirata: print(z.vydej_zvuk())
class Zvire { constructor(jmeno) { this.jmeno = jmeno; } vydejZvuk() { return "..."; } } class Pes extends Zvire { vydejZvuk() { return `${this.jmeno} štěká: Haf haf!`; } } class Kocka extends Zvire { vydejZvuk() { return `${this.jmeno} mňouká: Mňau!`; } } // Polymorfní cyklus const zvirata = [new Pes("Alík"), new Kocka("Micka")]; zvirata.forEach(z => console.log(z.vydejZvuk()));
class Zvire { public string $jmeno; public function __construct($jmeno) { $this->jmeno = $jmeno; } public function vydejZvuk(): string { return "..."; } } class Pes extends Zvire { public function vydejZvuk(): string { return $this->jmeno . " štěká: Haf!"; } } class Kocka extends Zvire { public function vydejZvuk(): string { return $this->jmeno . " mňouká: Mňau!"; } } $zvirata = [new Pes("Alík"), new Kocka("Micka")]; foreach ($zvirata as $z) { echo $z->vydejZvuk() . "\n"; }

Vizuální modelování: UML Class Diagram

Unified Modeling Language – celosvětový standard pro grafický návrh a dokumentaci tříd a systémů.

V diagramu tříd je každá třída znázorněna obdélníkem rozděleným na 3 horizontální oddíly:

«entity»
Uzivatel
- id : int
+ jmeno : string
- hesloHash : string
# role : string = "student"
+ prihlasSe(heslo: string) : bool
+ zmenHeslo(stare: string, nove: string) : void
- overHesloHash(heslo: string) : bool
1. Název třídy • 2. Atributy (stav) • 3. Metody (operace)

Značení viditelnosti (Visibility)

Znak Modifikátor Význam a dosah
+ public Veřejný člen – přístupný odkudkoli z celého programu.
- private Soukromý člen – přístupný pouze uvnitř těla této konkrétní třídy.
# protected Chráněný člen – přístupný ve třídě a ve všech jejích odvozených potomcích.
~ package Balíčkový přístup – v rámci stejného namespace / modulu.

Formát zápisu členů v UML:

[viditelnost] [nazev] : [datový typ] = [výchozí hodnota]
[viditelnost] [nazev]([parametr]: [typ]) : [návratový typ]

Podtržený text v UML značí statický člen (patřící celé třídě, nikoli instanci).

Vztahy mezi třídami v UML diagramech

Objekty v softwaru nežijí izolovaně – spolupracují, skládají se do větších celků a dědí své vlastnosti.

Typ vztahu UML grafický symbol Význam & vazba Reálný příklad

Shrnutí tématu & Kontrolní otázky

Zopakujte si základní principy objektového paradigmatu před přechodem k detailní anatomii třídy.

Rychlý přehled pro vývojáře SPŠ

  • OOP sdružuje související data (atributy) a logiku (metody) do jednoho celku – objektu.
  • Třída je vzor/plán v kódu, objekt je konkrétní živá instance v paměti haldy.
  • 4 pilíře: Abstrakce (vyber to podstatné), Zapouzdření (zamkni stav za metody), Dědičnost (znovupoužij předka), Polymorfismus (reaguj různě na stejný signál).
  • UML Class Diagram znázorňuje třídy v obdélníku se 3 oddíly a viditelností: + public, - private, # protected.
  • Vztahy: Kompozice (silné spojení), Agregace (volné spojení), Generalizace (dědičnost).
Častý omyl: Vytvoření třídy pro každou triviální funkci

OOP není cíl, ale nástroj. Pro jednoduché výpočty stačí čistá funkce. Objektový model dává smysl tam, kde existuje stav, který se v čase mění, a soubor pravidel pro manipulaci s ním.

Ověřte své znalosti (Kliknutím zobrazte řešení):

1. Jaký je rozdíl mezi třídou a instancí?
Třída je předpis v kódu (architektonický plán), zatímco instance je konkrétní objekt vytvořený v paměti RAM se svými vlastními hodnotami.
2. Proč děláme atributy soukromé (Private)?
Abychom zabránili neoprávněné manipulaci a zajistili, že jakákoli změna stavu projde přes validační logiku našich metod (Zapouzdření).
3. Co vyjadřuje polymorfismus v praxi?
Možnost volat metodu se stejným názvem na různých typech objektů, přičemž každý objekt vykoná svou specifickou implementaci.
4. Jaký je rozdíl mezi kompozicí a agregací v UML?
U kompozice (černý kosočtverec) je součást existenčně závislá na celku (auto → motor). U agregace (bílý kosočtverec) může prvek existovat samostatně (třída → žák).
