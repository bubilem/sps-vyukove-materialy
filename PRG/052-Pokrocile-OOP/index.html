Dědičnost v praxi: Odvození potomka z předka

Jak znovupoužít existující logiku bez duplikace kódu a předat parametry do konstruktoru předka.

Předek (Rodič) vs. Potomek (Dítě)

Potomek automaticky získává všechny atributy a metody rodiče. Může si přidat další své specifické atributy (např. Zamestnanec přidává plat k základním údajům ze třídy Osoba).

Volání konstruktoru rodiče:

  • Python: super().__init__(...).
  • JavaScript: super(...) – musí být zavoláno jako první řádek před použitím this!
  • PHP: parent::__construct(...).
Dědičnost & super
class Osoba: def __init__(self, jmeno, email): self.jmeno = jmeno self.email = email # Zamestnanec dědí z Osoba class Zamestnanec(Osoba): def __init__(self, jmeno, email, plat): super().__init__(jmeno, email) # Volání předka self.plat = plat z = Zamestnanec("Petr", "petr@sps.cz", 45000) print(z.jmeno, z.plat)
class Osoba { constructor(jmeno, email) { this.jmeno = jmeno; this.email = email; } } // Zamestnanec rozšiřuje Osoba class Zamestnanec extends Osoba { constructor(jmeno, email, plat) { super(jmeno, email); // Povinné volání super() this.plat = plat; } } const z = new Zamestnanec("Petr", "petr@sps.cz", 45000);
class Osoba { public function __construct( public string $jmeno, public string $email ) {} } class Zamestnanec extends Osoba { public float $plat; public function __construct($jmeno, $email, $plat) { parent::__construct($jmeno, $email); $this->plat = $plat; } } $z = new Zamestnanec("Petr", "petr@sps.cz", 45000);

Přepisování metod (Method Overriding)

Jak potomek upraví nebo rozšíří chování metody definované v rodičovské třídě.

Co znamená přepsání metody?

Pokud potomek definuje metodu se stejným názvem i parametry jako předek, nová implementace plně nahradí původní chování pro instance této podtřídy.

Rozšíření místo pouhého nahrazení

Často nechceme původní logiku zahodit, ale pouze k ní něco přidat. Pomocí super.metoda() zavoláme kód předka a k výsledku připojíme specializovanou operaci.

Overriding
class Uzivatel: def zobraz_profil(self): return "Základní uživatelský profil" class Admin(Uzivatel): # Přepsání metody předka def zobraz_profil(self): zaklad = super().zobraz_profil() return f"{zaklad} + [ADMINISTRÁTORSKÝ PANEL]" a = Admin() print(a.zobraz_profil())
class Uzivatel { zobrazProfil() { return "Základní uživatelský profil"; } } class Admin extends Uzivatel { // Přepsání metody předka zobrazProfil() { const zaklad = super.zobrazProfil(); return `${zaklad} + [ADMINISTRÁTORSKÝ PANEL]`; } } const a = new Admin(); console.log(a.zobrazProfil());
class Uzivatel { public function zobrazProfil(): string { return "Základní uživatelský profil"; } } class Admin extends Uzivatel { // Přepsání metody předka public function zobrazProfil(): string { $zaklad = parent::zobrazProfil(); return $zaklad . " + [ADMINISTRÁTORSKÝ PANEL]"; } } $a = new Admin(); echo $a->zobrazProfil();

Polymorfismus v akci: Síla společného rozhraní

Zpracování heterogenních kolekcí objektů jedním elegantním cyklem bez ošklivých větvení switch a if-else.

Špatně: Procedurální větvení if-else

Při přidání nového geometrického tvaru musíte dohledat všechny podmínky if typ == "trojuhelnik" v celém projektu a ručně je upravit. Snadno vznikne chyba.

Správně: Polymorfní volání metody

Cyklus pouze zavolá tvar.spocitejObsah(). Jakýkoli nový tvar stačí pouze naprogramovat a okamžitě funguje se zbytkem aplikace.

Duck Typing (Kachní typování)

„Pokud to chodí jako kachna a kváká jako kachna, pak je to kachna.“ V Pythonu a JS nemusí objekty ani dědit ze společné třídy – stačí, že mají metodu se stejným názvem.

Heterogenní kolekce
import math class Kruh: def __init__(self, r): self.r = r def obsah(self): return math.pi * self.r ** 2 class Obdelnik: def __init__(self, a, b): self.a, self.b = a, b def obsah(self): return self.a * self.b # Smíšený seznam různých objektů: tvary = [Kruh(5), Obdelnik(4, 6), Kruh(2)] celkovy_obsah = sum(t.obsah() for t in tvary) print(f"Celková plocha: {celkovy_obsah:.2f}")
class Kruh { constructor(r) { this.r = r; } obsah() { return Math.PI * this.r ** 2; } } class Obdelnik { constructor(a, b) { this.a = a; this.b = b; } obsah() { return this.a * this.b; } } const tvary = [new Kruh(5), new Obdelnik(4, 6)]; const celkem = tvary.reduce((sum, t) => sum + t.obsah(), 0); console.log(`Celková plocha: ${celkem.toFixed(2)}`);
class Kruh { public function __construct(public float $r) {} public function obsah(): float { return M_PI * $this->r ** 2; } } class Obdelnik { public function __construct(public float $a, public float $b) {} public function obsah(): float { return $this->a * $this->b; } } $tvary = [new Kruh(5), new Obdelnik(4, 6)]; $celkem = 0; foreach ($tvary as $t) { $celkem += $t->obsah(); } echo "Celková plocha: " . round($celkem, 2);

Abstraktní třídy a metody: Závazná šablona

Třídy, ze kterých nelze vytvořit instanci, slouží jako přísný předpis pro všechny odvozené potomky.

Proč potřebujeme abstrakci?

Nedává smysl vytvořit samotnou instanci new GeometrickyUtvar() – nevíme, jak vypadá ani jak spočítat obsah. Má ale smysl vytvořit Kruh či Ctverec. Abstraktní třída zaručí, že každý potomek MUSÍ metodu implementovat, jinak program vůbec nenastartuje.

Podpora v jazycích:

  • Python: Modul abc (Abstract Base Classes) a dekorátor @abstractmethod.
  • PHP: Klíčová slova abstract class a abstract function.
  • JavaScript: Nativní klíčové slovo chybí, simuluje se vyhozením výjimky v konstruktoru / metodě rodiče.
Abstraktní třída
from abc import ABC, abstractmethod class Platba(ABC): @abstractmethod def zaplat(self, castka): """Každý potomek musí tuto metodu naprogramovat!""" pass class KartaPlatba(Platba): def zaplat(self, castka): return f"Zaplaceno {castka} Kč platební kartou." # p = Platba() -> TypeError: Can't instantiate abstract class! p = KartaPlatba() print(p.zaplat(500))
class Platba { constructor() { if (new.target === Platba) { throw new Error("Nelze vytvořit instanci abstraktní třídy!"); } } zaplat(castka) { throw new Error("Metoda zaplat() musí být přepsána!"); } } class KartaPlatba extends Platba { zaplat(castka) { return `Zaplaceno ${castka} Kč kartou.`; } }
abstract class Platba { // Závazná abstraktní metoda abstract public function zaplat(float $castka): string; } class KartaPlatba extends Platba { public function zaplat(float $castka): string { return "Zaplaceno {$castka} Kč kartou."; } } // $p = new Platba(); -> Fatální chyba PHP! $p = new KartaPlatba(); echo $p->zaplat(500);

Rozhraní (Interfaces) & Architektonické kontrakty

Čistá smlouva o chování: Třída slibuje, jaké metody poskytne, bez sdílení vnitřní implementace.

Abstraktní třída vs. Rozhraní (Interface)

Zatímco třída může dědit pouze z jednoho rodiče (jednoduchá dědičnost v PHP/JS), může implementovat neomezený počet rozhraní (např. implements Loggable, Serializable, JsonSerializable).

Programování proti rozhraní

Místo závislosti na konkrétní třídě MysqlDatabaze vytvoříme interface DatabazeInterface. Aplikaci pak můžeme kdykoli bezpečně přepnout na PostgresDatabaze.

Interface
from typing import Protocol # Python Protocol = moderní strukturální rozhraní (PEP 544) class Odesilatel(Protocol): def odesli(self, zprava: str) -> bool: ... class EmailSender: def odesli(self, zprava: str) -> bool: print(f"Odesílám e-mail: {zprava}") return True def upozorni_uzivatele(notifikator: Odesilatel): notifikator.odesli("Vítejte ve škole!") upozorni_uzivatele(EmailSender())
// V TypeScriptu plný interface, v čistém JS konvence kontraktu class EmailSender { odesli(zprava) { console.log(`Odesílám e-mail: ${zprava}`); return true; } } class SmsSender { odesli(zprava) { console.log(`Odesílám SMS: ${zprava}`); return true; } } function upozorni(sluzba) { sluzba.odesli("Vítejte ve škole!"); }
interface OdesilatelInterface { public function odesli(string $zprava): bool; } class EmailSender implements OdesilatelInterface { public function odesli(string $zprava): bool { echo "Odesílám e-mail: $zprava\n"; return true; } } function upozorni(OdesilatelInterface $sluzba) { $sluzba->odesli("Vítejte ve škole!"); } upozorni(new EmailSender());

Kompozice vs. Dědičnost: Zlaté pravidlo OOP

„Upřednostňujte skládání objektů před hlubokou dědičností tříd“ (Favor composition over inheritance).

Past hluboké dědičnosti (IS-A)

Představte si Auto dědící z Motor, které dědí ze Stroj. Dědičnost vytváří extrémně pevnou vazbu. Změna v základní třídě může nečekaně rozbít desítky podtříd (tzv. Fragile Base Class problem).

Síla kompozice (HAS-A)

Auto má Motor jako instanční proměnnou. Můžete za běhu snadno vyměnit ElektroMotor za SpalovaciMotor bez jakéhokoli zásahu do třídy Auto!

Kompozice
class Motor: def nastartuj(self): return "Vrrrm! Motor běží." class Auto: def __init__(self, motor): # Kompozice: Auto MÁ motor (předaný zvenčí) self.motor = motor def jed(self): print(self.motor.nastartuj()) print("Auto se rozjíždí...") moje_auto = Auto(Motor()) moje_auto.jed()
class Motor { nastartuj() { return "Vrrrm! Motor běží."; } } class Auto { constructor(motor) { this.motor = motor; // Kompozice HAS-A } jed() { console.log(this.motor.nastartuj()); console.log("Auto se rozjíždí..."); } } const a = new Auto(new Motor()); a.jed();
class Motor { public function nastartuj(): string { return "Vrrrm! Motor běží."; } } class Auto { public function __construct(public Motor $motor) {} public function jed(): void { echo $this->motor->nastartuj() . "\n"; echo "Auto se rozjíždí...\n"; } } $a = new Auto(new Motor()); $a->jed();

OOP Antipatterny: Čeho se v kódu vyvarovat

Nejčastější začátečnické i architektonické chyby, které dělají kód neudržitelným.

1. God Object (Božská třída)

Jediná gigantická třída (např. SystemManager o 3000 řádcích), která ví a dělá úplně všechno – od připojení k databázi přes kreslení UI až po výpočet mezd.

Náprava: Princip jedné odpovědnosti (SRP). Rozdělte třídu na menší úzce zaměřené služby.

2. Lávový / Yo-Yo strom dědičnosti

Příliš hluboká dědičnost (5 a více úrovní). Při ladění chyby musí vývojář skákat z potomka do rodiče, prarodiče a praprarodiče jako s jo-jem.

Náprava: Omezte dědičnost na max 2–3 úrovně a zbytek řešte kompozicí.

3. Porušení Liskovové principu (LSP)

Potomek změní chování tak, že rozbije očekávání předka (např. třída Pstros dědí z Ptak, ale metoda let() vyhodí chybu, protože pštros létat neumí).

Náprava: Přehodnoťte abstrakci – např. vytvořte LetajiciPtak a Bezec.

4. Anemický doménový model

Třídy obsahují pouze holá veřejná data bez jakékoli logiky a metod (pouhé datové přepravky). Veškerá logika je rozptýlena v externích funkcích jako v procedurálním kódu.

Náprava: Přesuňte operace nad stavem přímo do metod daného objektu.

Závěrečné shrnutí bloku OOP & Kvíz mistrovství

Kompletní rekapitulace modulů 050, 051 a 052 – jste připraveni pro vývoj rozsáhlých aplikací!

Základní Desatero OOP pro studenty SPŠ:

  • Vždy chraňte stav objektu (Zapouzdření) a validujte vstupy v konstruktoru.
  • Atributy dělejte soukromé, ven pouštějte pouze bezpečné gettery a settery.
  • Používejte dědičnost pouze pro skutečný vztah IS-A, jinak volte kompozici.
  • Využívejte polymorfismus a zbavte se zbytečných řetězců podmínek if-else.
  • Stavte architekturu proti rozhraním (Interfaces) pro snadnou testovatelnost a výměnu modulů.
Navazující látka: Po zvládnutí OOP základů můžete pokračovat tématy 070 Teorie grafů a 071 Reprezentace grafu v kódu, kde již stavíme pokročilou třídu Graph!

Závěrečný kvíz mistrovství (Klikněte pro odpověď):

1. Lze vytvořit instanci abstraktní třídy pomocí new?
Ne. Abstraktní třída slouží výhradně jako šablona pro potomky. Pokus o instanciaci vyvolá fatální chybu či výjimku.
2. Jaký je hlavní rozdíl mezi abstraktní třídou a rozhraním?
Abstraktní třída může obsahovat hotový kód a stav (atributy) a dědit lze jen z jedné. Rozhraní obsahuje pouze prázdné signatury metod a třída jich může implementovat neomezeně mnoho.
3. Proč je často kompozice lepší než dědičnost?
Nevytváří pevnou vazbu. Komponenty lze za běhu programu vyměňovat (např. jiný motor v autě) a úprava jedné třídy nerozbije celý strom dědiců.
4. Co provede metoda __str__ v Pythonu a __toString v PHP?
Definuje, jak se má objekt reprezentovat jako textový řetězec při výpisu příkazem print/echo nebo při vložení do textové šablony.
